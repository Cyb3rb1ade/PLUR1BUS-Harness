## 1. Loop engineering

| Principle / mechanism | What it does | Evidence / measurement | Source | Applies to our harness how |
|---|---|---|---|---|
| **Loop = gather context → take action → verify work → repeat** | The canonical harness cycle; verification is a first-class phase, not an afterthought | Stated as the SDK's foundational pattern | [Anthropic, *Building agents with the Claude Agent SDK*](https://claude.com/blog/building-agents-with-the-claude-agent-sdk), Thariq Shihipar et al., 2025-09-29 | Make `verify` an explicit loop phase in ADR-001, with pluggable verifiers, not an implicit "model checks its own work" |
| **Loop until the model stops calling tools; no max-step cap** | Removes an arbitrary failure mode; the model owns termination | pi runs synchronously with no max-step limit across "seven different production projects"; author: "I never found a use case for that" | [Mario Zechner, *What I learned building an opinionated and minimal coding agent*](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/), 2025-11-30 | Default to unbounded steps; enforce budgets by **tokens and wall-clock**, not step count |
| **Submit/event asynchrony instead of request/response** | Client submits `Op` (UserTurn, Interrupt, Shutdown); core emits an event stream (message deltas, exec begin/end, patch applied, tokens used). UI is a pure event consumer | codex-rs: "the TUI subscribes to events; it does not call into the core engine synchronously"; ~70 crates, core engine reusable as a library | [Daniel Vaughan, *The codex-rs Architecture*](https://codex.danielvaughan.com/2026/03/28/codex-rs-rust-rewrite-architecture/), 2026-03-28 | **Adopt directly.** A TS core that emits a typed event stream makes TUI, daemon, HTTP API and tests all the same consumer. Interruption becomes just another `Op` |
| **Interrupt-and-redirect mid-turn** | User can steer without killing the session | Shipped feature in Hermes TUI alongside streaming tool output | [NousResearch/hermes-agent](https://github.com/nousresearch/hermes-agent) | Interrupt must cancel in-flight tool calls and *preserve* the partial assistant turn so the cache prefix survives |
| **Message queueing between turns** | Loop drains queued user messages after each turn, one-at-a-time or all-at-once | pi supports both modes | [Zechner 2025-11-30](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/) | Cheap to add; prevents the "user typed while agent worked" race |
| **Parallel tool calling** | Issue independent tool calls concurrently in one assistant turn | Anthropic's research system: parallel tool calling cut research time "by up to 90%" | [Anthropic, *How we built our multi-agent research system*](https://www.anthropic.com/engineering/multi-agent-research-system) | Highest-leverage single latency win. Requires tools to declare purity/idempotence so the scheduler knows what's safe to run concurrently |
| **Speculative tool execution (PASTE)** | Predict the next tool from recurring `(context, tool, arg-mapping, confidence)` patterns and pre-execute on slack resources while the model is still decoding | **48.5% reduction in average task completion time; 1.8× tool-execution throughput** on Deep Research Bench, SWE-Bench, ScholarQA. Tool execution is 35–61% of total request time | [Sui et al., *Act While Thinking* (PASTE)](https://arxiv.org/html/2603.18897v1), arXiv 2603.18897, 2026-03-19 | Only safe for **read-only / idempotent** tools. Design tool metadata (`readOnly`, `idempotent`, `destructive`) from day one so speculation is opt-in per tool |
| **Correctness via preemption, not rollback** | Speculative jobs run on slack resources only, are instantly preempted under contention, and are *promoted* (results committed) when the real request matches | PASTE has no rollback path; side effects are prevented structurally | [PASTE, arXiv 2603.18897](https://arxiv.org/html/2603.18897v1) | Mirror this: a speculative result is only ever *adopted*, never *undone* |
| **Typed failure classification bounds retry spend** | Classify failures (transient / schema / semantic / fatal) so retry multipliers are bounded per class | One of six mechanism families behind a measured 41% cost reduction | [Writer, *The Harness Effect*](https://arxiv.org/html/2607.06906v1), arXiv 2607.06906, July 2026 | ADR-001 should define a failure taxonomy with per-class retry budgets; unbounded retries are a documented cost sink |
| **Zero-token waiting** | Durable suspensions replace polling loops so waiting costs no tokens | Ibid., mechanism family 4 | [Writer, *The Harness Effect*](https://arxiv.org/html/2607.06906v1) | Long-running tools (builds, tests, deploys) should suspend the turn and resume on event, not be polled by the model |
| **Errors surfaced, success silent (back-pressure)** | Verification hooks return nothing on success and only errors on failure | HumanLayer's documented early mistake: running the full test suite flooded context; fix was selective execution with error-only output | [HumanLayer, *Skill Issue*](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents), 2026-03-12 | Tool-result formatter must have a "quiet on success" contract |
| **Hooks with exit-code semantics** | Lifecycle scripts run at tool-call / completion events; exit code `2` re-engages the agent, silence = success | Documented Claude Code hook convention | [HumanLayer, *Skill Issue*](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents) | Deterministic control flow without burning model turns |
| **Checkpoint + resume rather than restart** | Agents resume from failure points; state kept externally | Production lesson from Anthropic's research system, alongside full production tracing and rainbow deployments (gradual traffic shift so running agents aren't killed by a deploy) | [Anthropic, *multi-agent research system*](https://www.anthropic.com/engineering/multi-agent-research-system) | A memory-engine-centric harness gets this nearly free — but only if turn state is written to the engine *transactionally per step* |

## 2. Context engineering

| Principle / mechanism | What it does | Evidence / measurement | Source | Applies to our harness how |
|---|---|---|---|---|
| **Context is a finite attention budget; "context rot"** | Recall accuracy degrades as token count grows — longer windows enlarge the haystack, they don't improve needle-finding | Anthropic states the model's "ability to accurately recall information from that context decreases" with length; Chroma's context-rot study covered 18 models and found degradation compounds with low semantic similarity | [Anthropic, *Effective context engineering for AI agents*](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), Applied AI team, 2025-09-29; [HumanLayer](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents) citing Chroma | Treat context budget as a hard resource in ADR-003, with per-zone allocations and telemetry, not a soft warning |
| **"Right altitude" system prompts** | Neither brittle hardcoded logic nor vague guidance — "specific enough to guide behavior effectively, yet flexible enough to provide strong heuristics" | Anthropic's explicit framing | [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | Codify as a prompt review rule |
| **Minimal system prompt** | Modern RL-trained models need very little native prompting | pi's entire system prompt **including tool definitions is under 1,000 tokens**; the core prompt is **73 tokens**, plus injected AGENTS.md | [Zechner 2025-11-30](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/) | A strong counter-argument to a large system prompt. Every token in the stable zone is paid on every cache *write*; keep it small and let skills/memory carry specificity |
| **Less instruction is more (measured)** | Over-instruction in agent files actively harms | ETH Zurich study of 138 agentfiles: **LLM-generated CLAUDE.md/AGENTS.md hurt performance and raised token cost 20%+**; human-written files gave a modest **~4%** improvement. HumanLayer's own CLAUDE.md is under 60 lines | [HumanLayer, *Skill Issue*](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents) citing ETH Zurich | Do **not** auto-generate project instruction files from the memory engine. Curate them |
| **Two-zone prompt: static before dynamic** | Everything stable (tools → system → stable context) precedes everything volatile (history, user input, timestamps) | Writer's "cache-shape discipline" achieves **99.9% cache-hit rates**, pricing inputs at ~0.1× list | [Writer, *The Harness Effect*](https://arxiv.org/html/2607.06906v1) | **The single most important layout rule for ADR-010.** Ban timestamps, session IDs, token counters and "current time" from the stable zone |
| **Memory injected as a frozen snapshot at session start** | Memory renders into the system prompt once and does not change mid-session, explicitly to preserve prefix cache | Hermes: memory files are "injected into the system prompt as a frozen snapshot at session start"; writes persist to disk immediately but don't appear in context until the next session | [Hermes memory docs](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md) | **Direct conflict with a live memory engine.** Resolution: frozen snapshot in the *stable zone*, plus mid-session recall injected as *tool results in the volatile tail* — never by rewriting the system block |
| **Just-in-time retrieval over pre-loading** | Keep lightweight identifiers (paths, IDs, symbols); load content at runtime via tools | Anthropic's analogy: humans don't memorise corpora, they build indexes | [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | Recall returns *pointers + 1-line gists* by default; full text only on a second call |
| **Hybrid: agentic search first, semantic search only if needed** | Filesystem primitives (grep/glob/tail) are precise and transparent; embeddings add maintenance cost and staleness | Anthropic: start with agentic search, adopt semantic "only when performance demands justify it". OpenClaw's `memory_search` is hybrid vector+keyword *and degrades to keyword-only without an embedding provider* | [Claude Agent SDK blog](https://claude.com/blog/building-agents-with-the-claude-agent-sdk); [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory) | Ship FTS (SQLite FTS5) as the *guaranteed* tier and vectors as an optional accelerator. Hermes uses FTS5 for `session_search` |
| **Structured note-taking as external memory** | Persistent files (NOTES.md) updated during work, reloaded as needed | "Persistent memory with minimal overhead" | [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | The memory engine should expose a file-shaped view; models are fluent in files |
| **Metadata as a token-free signal** | File hierarchies, naming conventions and timestamps let the agent judge relevance without loading objects | Ibid. | [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | Recall results should carry path/date/tag metadata cheaply |
| **Layered compaction — cheapest layer first** | Claude Code: L1 zero-cost tool-result trimming → L2 prompt-cache optimisation → L3 full LLM summary as last resort. "Most auto-compactions never reach Layer 3" | Comparative teardown of three harnesses | [Justin3go, *Shedding Heavy Memories: Context Compaction in Codex, Claude Code, and OpenCode*](https://justin3go.com/en/posts/2026/04/09-context-compaction-in-codex-claude-code-and-opencode), 2026-04-09 **[secondary — reverse-engineering, not vendor doc]** | **Adopt the layering.** Never jump straight to an LLM summarisation call |
| **Compaction trigger thresholds (three real implementations)** | Claude Code: fires at `effective_window − 13,000` tokens, where effective window = context window − min(max_output, 20,000). OpenCode: only prunes when it can free >20,000 tokens, always preserving the most recent 40,000. Codex: triggers near the limit with aggressive head-trimming fallback | Ibid. | [Justin3go 2026-04-09](https://justin3go.com/en/posts/2026/04/09-context-compaction-in-codex-claude-code-and-opencode) **[secondary]** | Gives concrete numbers to calibrate ADR-003. The OpenCode "only act if the saving is worth it" guard is a good anti-thrash rule |
| **What survives compaction** | Codex: all user messages verbatim + tool-call references; drops assistant replies and tool result *content*. Claude Code: system prompt, up to 5 recently edited files, tool-call history; replaces older tool results with placeholders. OpenCode: last 40k tokens, last 2 user turns, skill outputs; older messages hidden by timestamp rather than physically deleted | Ibid. | [Justin3go 2026-04-09](https://justin3go.com/en/posts/2026/04/09-context-compaction-in-codex-claude-code-and-opencode) **[secondary]** | "Hide, don't delete" (OpenCode) is the right default for a memory-engine harness: the engine keeps the full record, context keeps a view |
| **Compaction summary must quote, not paraphrase** | Claude Code's 9-section summary prompt (original intent, technical concepts, files of interest, errors and fixes, problem-solving logic, user-message summary, TODOs, current work, next step) explicitly requires "directly quote key phrases" | Ibid. | [Justin3go 2026-04-09](https://justin3go.com/en/posts/2026/04/09-context-compaction-in-codex-claude-code-and-opencode) **[secondary]** | Structured, quote-preserving summaries; auto-replay the last user instruction after compaction (OpenCode's trick) so the agent doesn't feel amnesiac |
| **Compaction prompt tuning = recall first, then precision** | "Maximize recall to ensure your compaction prompt captures every relevant piece of information," then iterate to remove the unnecessary | [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | An eval-driven compaction prompt, not a hand-written one |
| **Pre-compaction memory flush** | A silent turn reminds the agent to write important context to memory *before* the summariser runs | OpenClaw's documented behaviour; skipped for read-only sandbox sessions | [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory) | **Adopt.** For a memory-engine harness this is the natural seam: compaction becomes "persist, then prune" |
| **Working vs long-term separation with different injection rules** | OpenClaw: `memory/YYYY-MM-DD.md` daily working notes are indexed for search but **not** injected into the bootstrap prompt; `MEMORY.md` (curated long-term) and `USER.md` are | [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory) | Three tiers for ADR-003: **always-injected** (tiny, curated), **searchable** (large, indexed), **archival** (cold) |
| **Truncate the injected copy, keep the file intact** | If MEMORY.md exceeds the bootstrap budget, OpenClaw keeps disk intact and truncates the injected copy — and this is documented as a signal to reorganise | Ibid. | [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory) | Copy the behaviour but **fail loudly**: see OpenClaw issue #142393 below, where silent truncation dropped legitimate context |
| **Hard caps with agent-visible enforcement** | Hermes: MEMORY.md capped at **2,200 chars**, USER.md at **1,375 chars**; target ~8–15 and ~5–10 entries; proactive consolidation at 80% capacity; memory does **not** auto-compact — an over-limit write returns an error forcing the agent to consolidate in the same turn | [Hermes memory docs](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md) | **Strong pattern.** Backpressure-by-error beats silent eviction: the model is the one with the taste to decide what to drop |
| **Session search as unbounded recall without token cost** | SQLite + FTS5 full-text over all past conversations, queried on demand | Hermes `session_search`; Hermes also adds LLM summarisation over results for cross-session recall | [Hermes memory docs](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md); [hermes-agent repo](https://github.com/nousresearch/hermes-agent) | The memory engine's read path should be FTS5-backed and callable as a tool; unbounded history at zero standing token cost |
| **Cross-session handoff artifacts** | Initializer agent creates `init.sh`, `claude-progress.txt` and a baseline git commit; a JSON feature list with every feature initially marked **failing**; one feature per session; git commits as checkpoints; a fixed session-start routine (check cwd → read git log → read progress file → read feature list → run e2e smoke test) | Compaction alone proved insufficient; even a frontier model failed to build production-quality apps without these constraints | [Anthropic, *Effective harnesses for long-running agents*](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents), 2025-11-26 | This is the blueprint for "memory engine as session bootstrapper". The **features-default-to-failing** trick is a cheap, high-value anti-premature-completion device |
| **Non-blocking recall** | Nothing in the reviewed sources describes recall on the critical path; the pattern everywhere is *recall is a tool call* or *recall is a pre-built snapshot* | Hermes freezes at session start; OpenClaw injects at session start and searches on demand; Anthropic recommends JIT tool-based retrieval | Multiple, above | Build the prompt from a snapshot the engine maintains **ahead of the turn**; never block TTFT on a live embedding query. See §4 |

## 3. Token efficiency and caching

| Principle / mechanism | What it does | Evidence / measurement | Source | Applies to our harness how |
|---|---|---|---|---|
| **Prefix order is fixed: tools → system → messages** | Caching builds prefixes in that strict order; a change at any level invalidates that level *and everything after it* | Vendor-documented invalidation matrix | [Anthropic, *Prompt caching*](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) | Our prompt builder must assemble in exactly this order and hash each zone so we can *detect* accidental invalidation in tests |
| **Cache writes happen only at the breakpoint; reads look backward up to 20 blocks** | Marking a block writes exactly one entry (hash of the prefix ending there). On the next request the system hashes at your breakpoint and walks back at most **20 positions**. Consecutive `tool_use` blocks count as one position; likewise consecutive `tool_result` blocks | Ibid. | [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) | Put the breakpoint on the **last block identical across requests**. As long as a turn adds <20 blocks, the trailing breakpoint keeps hitting — this is what makes append-only conversation growth cheap |
| **Max 4 cache breakpoints; four-tier strategy** | Tier 1 tools, Tier 2 instructions, Tier 3 large stable context (RAG/memory snapshot), Tier 4 conversation tail. Each tier cached independently so updating docs doesn't invalidate tools | Ibid. | [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) | **Map our zones onto exactly these four tiers.** Memory snapshot belongs in Tier 3, never Tier 2 |
| **Minimum cacheable prefix is model-dependent (512 / 1,024 / 2,048 / 4,096 tokens)** | Below the minimum nothing caches — **and no error is returned**; you must inspect `usage` | Ibid. (table spans 512 for the newest models up to 4,096 for others) | [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) | A harness with a 73-token system prompt (pi-style) **cannot cache the system zone at all**. Either accept that, or deliberately pad Tier 2/3 with genuinely useful stable content to clear the floor |
| **Cache economics: write 1.25× (5 min) or 2.0× (1 h); read 0.1× (0.025× on newest)** | `total_input = cache_read + cache_creation + input`. `input_tokens` counts only what follows the last breakpoint | Ibid. Example: Sonnet-class base $2/MTok → 5m write $2.50, 1h write $4.00, read $0.20 | [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) | Break-even: a 5-minute write pays for itself after **~1.28 reads**. So caching is worth it from the *second* turn onward — which means caching should be **on by default**, not an optimisation flag |
| **Silent cache killers** | Changing tool definitions, toggling web search/citations, changing speed or effort settings, adding/removing images, changing `tool_choice`, non-deterministic JSON key order in tool schemas, and thinking-block handling on older models all invalidate | Ibid., full invalidation matrix | [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) | **Serialise tool schemas with sorted keys.** Add a CI test that hashes the rendered tools+system zone across two synthetic turns and fails on drift. This is the highest-ROI test in the repo |
| **Cache-shape discipline yields 99.9% hit rate** | Two-zone prompt design | Writer harness measured **99.9% cache hits**, inputs effectively priced at ~0.1× list | [Writer, *The Harness Effect*](https://arxiv.org/html/2607.06906v1) | Target metric for ADR-010: publish cache-hit rate per session as a first-class telemetry field |
| **Harness-only changes move the whole cost curve** | Swapping *only* the orchestration layer, holding model and task constant: **38% fewer tokens/task (14.2k → 8.8k), 41% lower cost ($0.21 → $0.12), 44% lower median latency (48s → 27s)**, quality parity (0.78 → 0.81, n=22, directional). Quality-per-dollar **+82%**; task-completions per million tokens **+68%**. Gains held across 6 models / 3 weight classes / 5 vendors, 33%–61% cost reduction | 33 authors, Writer Inc. | [Writer, *The Harness Effect*](https://arxiv.org/html/2607.06906v1), arXiv 2607.06906, July 2026 | The headline justification for this project. Note the caveat: **n=22 tasks, quality delta is directional, not significant** |
| **Six mechanism families that produce those numbers** | (1) cache-shape discipline, (2) structured compaction via typed checkpoints — converts quadratic history replay to linear growth, (3) context offload to subagents and files, (4) zero-token waiting, (5) failure-spend governance, (6) model-agnostic floor (native tool calling + schema hygiene) | Ibid. | [Writer, *The Harness Effect*](https://arxiv.org/html/2607.06906v1) | Use these six as the section headings of ADR-010 |
| **The harness controls most input-side cost terms** | System prompt, history, tool schemas and retrieval — 4 of 5 input terms — plus retry multipliers, are harness-owned, not model-owned | Ibid. | [Writer, *The Harness Effect*](https://arxiv.org/html/2607.06906v1) | Budget enforcement belongs in the prompt builder, not in prompts asking the model to be brief |
| **MCP tool schemas are a standing tax** | pi measured MCP at **13.7k–18k tokens of overhead per server**, ~**7–9% of context per session**, and rejected MCP in favour of CLI tools with READMEs (progressive disclosure: the agent reads docs only when needed) | [Zechner 2025-11-30](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/) | Corroborated by HumanLayer, who replaced a Linear MCP server with a CLI wrapper plus 6 usage examples | Default to a small native toolset; expose everything else as CLI + docs. If MCP is supported, make servers lazily/selectively enabled and count their tokens in telemetry |
| **Progressive disclosure via skills** | SKILL.md loaded as a user message on activation; skill directories can layer additional markdown files | [HumanLayer, *Skill Issue*](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents) | Anthropic has shipped experimental MCP tool *search* for the same reason | Memory engine should serve skills the same way: index everything, inject nothing until activated |
| **Minimal toolset beats broad toolset** | pi ships four core tools — read (2,000-line default with offset/limit), write, edit (exact-text match), bash — with grep/find/ls as optional read-only extras | [Zechner 2025-11-30](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/) | Anthropic independently warns against "bloated tool sets that cover too much functionality" ([context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)) | Start with ~5 tools. Each new tool must justify its permanent token rent |
| **Dual-channel tool results: text for the model, structured data for the UI** | Same tool call produces an LLM-facing string and a UI-facing object | pi validates args with TypeBox + AJV and returns both | [Zechner 2025-11-30](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/) | **Adopt for a TS harness** — TypeBox/AJV is directly applicable, and the split is what lets you render rich UI without paying tokens for it |
| **Zero-context-cost multi-step pipelines** | Python scripts call tools over RPC, collapsing an N-step tool pipeline into a single turn | Hermes: "collapsing multi-step pipelines into zero-context-cost turns" | [hermes-agent repo](https://github.com/nousresearch/hermes-agent) | Very strong idea: expose the tool layer over RPC so the model can write a script that orchestrates 20 calls for the token cost of one |
| **Code generation as the compression mechanism** | Generated code is "precise, composable, and infinitely reusable" versus repeated tool invocations | [Claude Agent SDK blog](https://claude.com/blog/building-agents-with-the-claude-agent-sdk) | Same conclusion as Hermes RPC, from the other direction |

## 6. Self-improvement loops (memory consolidation, skill mining, evals)

| Principle / mechanism | What it does | Evidence / measurement | Source | Applies to our harness how |
|---|---|---|---|---|
| **Sleep-time compute: think offline about context before queries arrive** | Pre-compute inferences over a context between sessions so test-time work shrinks | **~5× reduction in test-time compute** for equal accuracy on Stateful GSM-Symbolic and Stateful AIME; **up to +13% and +18% accuracy** respectively; **2.5× lower average cost per query** when amortised across related queries. Effectiveness correlates strongly with **query predictability** | [Lin, Snell, Wang, Packer, Wooders, Stoica, Gonzalez, *Sleep-time Compute: Beyond Inference Scaling at Test-time*](https://arxiv.org/abs/2504.13171), 2025-04-17 | **The strongest evidence in this dossier for an offline memory-engine phase.** Note the condition: gains depend on *predictable* future queries — so consolidation should be steered by observed query patterns, not run blindly |
| **Generative-agents retrieval score: recency × importance × relevance** | Recency = exponential decay, factor **0.995** per sandbox hour; importance = model-rated 1–10 poignancy; relevance = cosine similarity. Combined as a weighted sum (all α = 1 in the paper), normalised to [0,1] | Foundational memory-stream design | [Park et al., *Generative Agents*](https://ar5iv.labs.arxiv.org/html/2304.03442), arXiv 2304.03442 | A concrete, implementable default scoring function for the memory engine's recall ranker |
| **Reflection triggered by accumulated importance, not by clock** | Reflection fires when the summed importance of recent events exceeds a threshold (**150** in the paper), ≈2–3× per simulated day. It asks the model for the "3 most salient high-level questions" over the 100 most recent records and builds a reflection tree whose insights cite their supporting memories | Ibid. | [Generative Agents](https://ar5iv.labs.arxiv.org/html/2304.03442) | **Prefer importance-accumulation triggers over cron.** OpenClaw's cron-at-3am design is exactly what produced its runaway-loop bug (§7) |
| **Reflection is measurably load-bearing** | TrueSkill μ: full architecture **29.89** > no-reflection **26.88** > no-reflection/planning **25.64** > crowdworker baseline **22.95** > no-memory/reflection/planning **21.21**. Full vs no-memory effect size **d = 8.16**; all pairwise differences p<0.001 except the two lowest | Ibid., ablation study | [Generative Agents](https://ar5iv.labs.arxiv.org/html/2304.03442) | Rare *quantified* evidence that consolidation is not hype. Caveat: the metric is believability in a simulation, not task success |
| **Three-phase consolidation (light / REM / deep)** | Light: read recent short-term recall, daily files, redacted transcripts; stage candidates; record reinforcement signals — **no writes to long-term memory**. REM: build theme summaries, record reflection signals — **no writes**. Deep: weighted scoring, rehydrate snippets, threshold gates, model-assisted consolidation deciding add/merge/supersede | [OpenClaw dreaming docs](https://docs.openclaw.ai/concepts/dreaming) | The staged, write-only-at-the-end design is good. **Copy the structure; fix the triggering and dedupe** |
| **Explicit consolidation scoring weights** | relevance **0.30**, frequency **0.24**, query diversity **0.15**, recency **0.15**, consolidation **0.10**, conceptual richness **0.06**. Config: `maxPriorEntryLossFraction` default **0.25**, `maxPromotedSnippetTokens` default **160** | [OpenClaw dreaming docs](https://docs.openclaw.ai/concepts/dreaming) | A ready-made starting weight vector. The **"loss fraction" guard** (a consolidation pass may not destroy more than 25% of prior entries) is an excellent safety invariant |
| **Model emits operations, a validator applies them** | The consolidation model returns structured add/merge/supersede operations, **not prose**; a deterministic validator enforces prior-entry preservation, source attribution and file-size compliance; prior versions backed up | Ibid. | [OpenClaw dreaming docs](https://docs.openclaw.ai/concepts/dreaming) | **Adopt exactly.** Never let a model write the memory file directly |
| **Consolidation runs in fresh contexts** | Diary and consolidation completions use fresh contexts that don't retain conversation sessions, preventing diary artifacts from becoming promotion sources (a self-reinforcement loop) | Ibid. | [OpenClaw dreaming docs](https://docs.openclaw.ai/concepts/dreaming) | Guards against memory eating its own output — a real risk for any consolidation engine |
| **Auditable dream diary** | A human-readable `DREAMS.md` records phase summaries alongside machine state in SQLite | [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory) + [dreaming docs](https://docs.openclaw.ai/concepts/dreaming) | **Non-negotiable.** Unauditable consolidation is how OpenClaw users discovered garbage in MEMORY.md only after it had accumulated |
| **Bounded background concurrency** | Dreaming shares a global background-work budget: max **3 concurrent runs system-wide**, up to 3 slots for memory-core; diary generation and deep consolidation each consume a slot | [OpenClaw dreaming docs](https://docs.openclaw.ai/concepts/dreaming) | Necessary but, as issue #65550 shows, **insufficient without dedupe + a circuit breaker** |
| **Skill mining / procedural memory** | Hermes: skills are agent-curated procedural memory with "periodic nudges", they "self-improve during use", and new ones are created autonomously after complex tasks; compatible with the agentskills.io open standard, shared via a Skills Hub | [hermes-agent repo](https://github.com/nousresearch/hermes-agent) | The mechanism is clearly described; **the evidence that it improves outcomes is not.** See the counter-evidence immediately below |
| **Counter-evidence: autonomous skill generation misfires** | User-reported: self-improvement **overwrites manual edits and user customisations**; generates "bizarre/erroneous skills" with flawed logic (one example: a generated skill dropped a production-branch constraint); memory and skill lists grow unbounded | **[secondary — aggregator summarising Reddit/X reports, 2026-07-12]** | [AI Agent Store, *20 Biggest Problems with Hermes Agent*](https://aiagentstore.ai/agentic-ai-and-workflow-automation/en/the-20-biggest-problems-with-hermes-agent-what-thousands-of-reddit-and-x-users-are-actually-struggling-with-ranked) | **Gate every mined skill behind human review before activation**, and never let mining overwrite a human-authored artifact. Hermes' own `memory.write_approval: true` setting (which stages background self-improvement writes for review) exists for precisely this reason — but it is **off by default** |
| **Approval gates for background writes** | `memory.write_approval: true` stages all saves, including background self-improvement updates, for user review; `memory_notifications: off\|on\|verbose` controls noise | [Hermes memory docs](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md) | Make the equivalent **on by default** for anything the agent learned about *itself*, off for facts it learned about the *world* |
| **Eval practice: start small, judge end states** | Begin with **~20 test queries** representing real usage; LLM-as-judge with a single prompt scoring factual accuracy, citation accuracy, completeness, source quality and tool efficiency on 0.0–1.0; keep human testing for edge cases and subtle bias; **judge final outcomes, not intermediate steps**, for state-mutating tasks | [Anthropic multi-agent](https://www.anthropic.com/engineering/multi-agent-research-system) | A 20-case golden set is achievable in Phase 0 and is the cheapest guard against harness regressions |
| **Harness changes are measurable and large in benchmarks** | Terminal-Bench 2.0: the same model ranked **#33 inside Claude Code but #5 in a different harness**; separately, "harness setup alone can swing benchmarks by 5+ percentage points" | [HumanLayer, *Skill Issue*](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents) (rank figure); [awesome-harness-engineering](https://github.com/ai-boost/awesome-harness-engineering) (5-point figure, **[secondary]**) | Benchmark the harness, not just the model. Also a warning: benchmark rankings are harness-confounded |
| **Ship-first discipline (anti-hype)** | "We only spend time on harness configuration to the extent that it's actually enabling us to ship more high-quality code faster." What failed: preemptive optimisation, dozens of unused skills/servers, running full test suites, micro-managing subagent tool access. ### What is hype vs. what holds up

- **Holds up (quantified):** prompt-cache-shape discipline (99.9% hit rate; 38%/41%/44% token/cost/latency wins); parallel tool calling (up to 90% time reduction); layered compaction; subagent context isolation; sleep-time compute (5× test-time compute reduction, +13–18% accuracy); reflection (TrueSkill ablation, d=8.16); speculative tool execution (48.5% latency reduction); cold-start surgery (~80% TTFT reduction, measured).
- **Plausible but under-evidenced:** autonomous skill mining improving task success (mechanism documented by Hermes; outcome evidence is negative-leaning from user reports); "dreaming" improving downstream answers (OpenClaw documents the mechanism in detail but publishes **no** quality measurement); dynamic multi-agent topology (+12–23%, secondary citation only).
- **Actively cautionary:** multi-agent as a default (15× tokens; 80% of variance explained by token spend alone); cron-driven consolidation (see §7).

Hybrid search silently degrades to keyword-only without an embedding provider. Imported memories stay separate rather than merging | [OpenClaw dreaming docs](https://docs.openclaw.ai/concepts/dreaming); [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory) |

### What "better than OpenClaw and Hermes" means operationally

Derived directly from the documented failures above — these are testable acceptance criteria, not aspirations:

1. **Compaction can never deadlock.** Summarisation must run over a *bounded slice* (chunked/hierarchical), sized so the summariser prompt is provably under the window regardless of session size. Beats OpenClaw [#20760](https://github.com/openclaw/openclaw/issues/20760), [#25620](https://github.com/openclaw/openclaw/issues/25620).
2. **A single tool result can never exceed the budget.** Truncate-with-pointer at the tool boundary (result stored in the memory engine, a handle returned). Removes the "read one huge file and the session is dead" class entirely.
3. **No silent truncation, ever.** If the injected memory copy is clipped, the harness emits a visible warning and a deferral record rather than dropping the tail. Beats OpenClaw [#142393](https://github.com/openclaw/openclaw/issues/142393).
4. **Consolidation has dedupe, a circuit breaker and a spend cap.** Content-hash dedupe on candidates; max runs per hour; hard per-cycle token/dollar cap that aborts the cycle. Beats OpenClaw [#65550](https://github.com/openclaw/openclaw/issues/65550) (94 sessions / 65 min / $4.35).
5. **Promotion requires demonstrated utility.** Never promote `recalls = 0`, and make sure the recall counter actually covers the paths that can be promoted — the inverted-incentive bug in [#142393](https://github.com/openclaw/openclaw/issues/142393) is a pure design error worth encoding as a test.
6. **Consolidation is importance-triggered, not cron-triggered** (Generative Agents' accumulated-importance threshold), with cron only as a floor. Removes the whole class of "3 a.m. job chewed stale candidates".
7. **Memory is live within a session without breaking the cache.** Hermes freezes memory to protect the prefix; we get both by keeping the frozen snapshot in the cached zone and delivering mid-session recall as tool results in the uncached tail.
8. **Budget and cost are first-class.** Per-session and per-subagent token/dollar budgets with enforcement, plus visible accounting. Directly addresses Hermes' documented absence of any cost governance.
9. **Model switching does not cost a full re-read.** Maintain per-model cached prefixes, or warn-and-confirm before a switch that will invalidate. Addresses the Hermes FAQ's documented cache-key behaviour.
10. **Verification is structural, not self-reported.** External verifiers (typecheck/test/lint gates, features-default-to-failing lists) decide success. Directly addresses the #1 Hermes complaint and Anthropic's "judge end states" guidance.
11. **Self-improvement never overwrites human-authored artifacts,** and mined skills are inactive until reviewed. Addresses Hermes complaints #2 and #9; Hermes' own `write_approval` flag should be our default-on.
12. **Environment discovery is continuous, not a startup snapshot** (or at minimum re-probed in the background with a cache), fixing the `bash -l` / launchd PATH class of bugs.
13. **Subagents are fully observable** — every subagent is a real, replayable session in the memory engine. This is the concrete answer to pi's "black box within a black box" objection, which neither OpenClaw nor Hermes addresses.
14. **Auto-compaction thresholds are computed from measured token counts and unit-tested.** Claude Code shipped a regression where auto-compact fired every 1–2 minutes at **8% context usage with 882k tokens free**, invalidating cache and forcing CLAUDE.md re-injection ([anthropics/claude-code#52981](https://github.com/anthropics/claude-code/issues/52981), v2.1.112) — a reminder that threshold logic needs tests, not just a constant.

## Top 15 design rules, ranked

1. **Two-zone prompt: everything stable before anything volatile; nothing time-varying above the last breakpoint.** 99.9% cache hit rate and ~0.1× effective input pricing follow from this one rule. — [Writer, *The Harness Effect*](https://arxiv.org/html/2607.06906v1); [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
2. **Build the core as an async submit/event engine with thin clients (TUI, daemon, HTTP, tests all consume the same event stream), and run it as a resident process.** Cold start is ~75% reusable overhead — 13s per query without reuse. — [codex-rs architecture](https://codex.danielvaughan.com/2026/03/28/codex-rs-rust-rewrite-architecture/); [claude-agent-sdk-typescript#33](https://github.com/anthropics/claude-agent-sdk-typescript/issues/33)
3. **No network call and no subprocess spawn on the prompt-build path; probe capabilities from cache with background refresh; use the user's typing window.** Measured ~4.3s → ~0.9s submit-to-dispatch. — [Hermes PR #59332](https://github.com/NousResearch/hermes-agent/pull/59332)
4. **Layer compaction cheapest-first (trim tool results → protect cache prefix → LLM summary last), and hide rather than delete.** Most compactions should never reach an LLM call. — [Justin3go 2026-04-09](https://justin3go.com/en/posts/2026/04/09-context-compaction-in-codex-claude-code-and-opencode) **[secondary]**
5. **Compaction must be un-deadlockable and tool results must be bounded at the tool boundary.** The failure is documented, reproducible and closed-as-not-planned upstream. — [openclaw#20760](https://github.com/openclaw/openclaw/issues/20760)
6. **Parallel tool calls, with per-tool `readOnly`/`idempotent`/`destructive` metadata; speculatively pre-execute only read-only tools, preempt rather than roll back.** Up to 90% research-time reduction; 48.5% task-time reduction. — [Anthropic multi-agent](https://www.anthropic.com/engineering/multi-agent-research-system); [PASTE arXiv 2603.18897](https://arxiv.org/html/2603.18897v1)
7. **Keep the toolset small and pay for schemas consciously; prefer CLI-plus-docs and progressive disclosure over always-loaded MCP schemas.** MCP measured at 13.7k–18k tokens per server, 7–9% of context. — [Zechner 2025-11-30](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/); [HumanLayer](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents)
8. **Three memory tiers with different injection rules: always-injected (small, curated, capped), searchable (FTS5 first, vectors optional), archival.** Enforce caps by returning an error to the agent, not by silent eviction. — [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory); [Hermes memory docs](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md)
9. **Recall is just-in-time and off the critical path: return pointers and gists, fetch bodies on a second call, and pre-build the snapshot before the turn starts.** — [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); [Claude Agent SDK](https://claude.com/blog/building-agents-with-the-claude-agent-sdk)
10. **Flush to memory before compacting** ("persist, then prune"), which is the natural seam for a memory-engine harness. — [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory)
11. **Consolidation: staged phases, importance-accumulation trigger, explicit scoring weights, all-gates-must-pass promotion, model emits typed operations that a deterministic validator applies, a bounded prior-entry loss fraction, and an auditable diary — plus dedupe, a circuit breaker and a hard spend cap.** — [Generative Agents](https://ar5iv.labs.arxiv.org/html/2304.03442); [OpenClaw dreaming docs](https://docs.openclaw.ai/concepts/dreaming); [openclaw#65550](https://github.com/openclaw/openclaw/issues/65550)
12. **Offline (sleep-time) pre-computation is worth building, steered by observed query patterns.** ~5× test-time compute reduction, +13–18% accuracy, 2.5× lower per-query cost — conditional on query predictability. — [Lin et al., arXiv 2504.13171](https://arxiv.org/abs/2504.13171)
13. **Subagents: depth 1 by default, typed contracts (objective / scope / forbidden / output schema / token cap ≤ ~2k), 25-turn and 5-minute defaults, citations required, results enter as `tool_result` with provenance, and every subagent is a replayable session.** — [Goose subagents](https://goose-docs.ai/docs/guides/context-engineering/subagents/); [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); [Claude subagents](https://claude.com/blog/subagents-in-claude-code); [Zechner](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)
14. **Gate fan-out behind a budget and always benchmark it against a single agent given the same tokens.** Multi-agent ≈15× chat tokens; token spend alone explains 80% of performance variance. — [Anthropic multi-agent](https://www.anthropic.com/engineering/multi-agent-research-system)
15. **Verification is external and structural, errors-only on the wire; success is silent. Keep a ~20-case golden eval set, judge end states, and treat the harness itself as the thing under test.** Same model: rank #33 in one harness, #5 in another. — [Anthropic multi-agent](https://www.anthropic.com/engineering/multi-agent-research-system); [HumanLayer](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents); [Anthropic long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

**Ranking rationale:** 1–3 are pure wins with measured effects and no architectural downside, and 2 in particular is expensive to retrofit. 4–7 are the loop/context mechanics that everything else sits on. 8–12 are the memory-engine differentiators (our thesis). 13–15 are guardrails that stop the previous twelve from being undone.

- **OpenClaw publishes no quality measurement for dreaming** — the mechanism is documented in unusual detail, the benefit is not measured anywhere I could find. Contrast with the Generative Agents ablation, which does quantify reflection (in a simulation, for believability, not task success).

- **Claude Code's internal compaction thresholds** (`effective_window − 13,000`, etc.) come from a third-party reverse-engineering write-up, not Anthropic documentation. Directionally useful; do not treat the constants as contractual.
- **Goose's context revision/compaction** is not described in its subagents documentation; I did not locate a Goose compaction doc.
- **No primary source found** for measured cold-start numbers of Claude Code or the Codex CLI specifically (the codex-rs article makes qualitative claims — "starts in milliseconds" — with no measurement).
