# Apple Foundation Models as a local model provider — implementation plan

**Goal.** Offer Apple's on-device Foundation Model (`system`, through `fm serve --socket`) as an optional macOS-only local provider `apple-fm`: a managed Unix-socket transport, a supervised `fm serve` sidecar, discovery and catalog rows, locality by model (`pcc` never offered), a 4k-context guard for roles, doctor rows, and later a decision backend behind the German gate and a node offer for D119, as specified in [`2026-10-31-apple-foundation-models-design.md`](../specs/2026-10-31-apple-foundation-models-design.md) (cited as "spec §n"; register entry proposed **D122**).

**Architecture.** Provider adapter, transport, discovery, privacy and guard extend existing TypeScript packages (`packages/providers`, `packages/core`, `packages/config-schema`), justified in spec AD10 (D120 path B, existing TypeScript, no new component). The `fm serve` sidecar slot, the doctor rows and the setup notice are supervisor and CLI work, so Rust, in `crates/plur1bus/src/supervisor/` and `crates/plur1bus/src/commands/`, following ADR-012's supervised-child model.

**Status.** Plan only, no product code. Q1–Q10 of spec §8 are open; none blocks AF0 to AF3 (recommendations are the defaults used below). AF4 waits for D119's node bridge, AF5 for Q7 and Q8.

**Constraints.**
- No `sudo` by the harness or an agent, no password handling, no `fm license` run by any WP or test. The licence is accepted by the person in Terminal; code detects it (`fm license --status`) and shows `sudo fm license` as text.
- No network in tests and **no real `fm` in CI**: a fake `fm serve` over a Unix socket (TypeScript) and a fake `fm` executable (Rust). Fixtures are synthetic. Live probes run only on the owner's Mac behind `PLUR1BUS_APPLE_FM_LIVE=1` and are never CI jobs.
- JSON Schema stays the single source: every RPC addition (`daemon.status` `detail`, compute runtime family) carries `x-stability: "experimental"`, `x-since` and a closed shape; no new RPC error code (new reason strings only, in `docs/errors.md`); every config key `x-restart` and `x-tier` (ADR-013); TDD (red test first); `erasableSyntaxOnly`; de and en strings complete for web.
- Rust: `#![forbid(unsafe_code)]` where the crate already does, workspace clippy lints, no new crate or dependency (the health client is plain `std`; `docs/dependency-policy.md` is untouched). `scripts/lint-hygiene.mjs` stays green (supervisor dependency budget HYG-005/006).
- **Every Rust package is done by a Claude agent, never Codex** (owner preference). TypeScript packages: the controller's choice (Sonnet-suitable). One branch and one ready PR per package; no CI polling (push, open the PR, report the number, stop); no force-push, rebase, amend or stash; commits carry the owner's identity.

## Best first WP

**AF1.** It has no dependency and no pending owner answer, runs entirely in CI (fake server, temp directories), and fixes the contract everything else leans on: the managed-socket guard, the always-streaming quirk handled by content type, the model allowlist, and the fake `fm serve` that AF2 to AF5 reuse. AF0 starts at the same time on the owner's Mac (a quarter of a day) and only adjusts defaults (`includeUsage`, `allowMissingDone`, concurrency cap, the deadline constant); AF1 is tolerant of both answers to U1 by design. AF3 may start in parallel once AF0 reports, because its only coupling to AF2 is the socket path (`<home>/run/apple-fm/fm.sock`), pinned by a parity fixture.

## Gates and order

1. AF0 and AF1 in parallel. 2. AF2 after AF1. 3. AF3 after AF0 (parallel to AF2). 4. AF4 when D119's node bridge exists. 5. AF5 after AF2, AF3 and the owner's answers.

## Acceptance (v1, AF0 to AF3)

- With `appleFm.enabled` on an eligible Mac (macOS 27 or newer, Apple Silicon, licence agreed by the person, Apple Intelligence ready) `plur1bus daemon status` shows the slot `ready`, `plur1bus model scan --provider apple-fm` lists exactly `system` with window 4096, and `modelRoles.decision = apple-fm/system` classifies through the router; no TCP listener belongs to the slot and `fm` was started with `--socket` only.
- Without the licence the slot is `blocked`, nothing is spawned in a loop, `1staid check` fails `apple-fm.license` with the text `sudo fm license` for the person, and no WP, test or harness code ever runs `sudo` or `fm license`.
- `pcc` is unreachable: not in the catalog, refused by the adapter with zero bytes written, `E_DENIED` reason `local-only` under `privacy.localOnly`.
- `modelRoles.chat = apple-fm/system` is refused with the window and floor named; a `decision` request over the bound is `context_overflow` before I/O and the consumer fallback runs.
- The socket lives in a 0700 directory under `run/`, never `/tmp`; a path over 103 bytes makes the provider unavailable with a hint.
- On every other OS and on Intel the rows read `skipped`, nothing is spawned, and the same `config.json` loads.
- All of it green on the CI targets with no real `fm`, no network; generated docs and schema fixtures current.

## Out of scope

`pcc` (Q6), a Swift helper, on-demand start and idle stop (Q10), chunking long inputs to fit 4,096 tokens, any chat or agent role on Apple FM, accepting Apple's licence in any form, embeddings or reranking, a TCP mode, and any GUI page beyond the model picker's `context-too-small` reason.
