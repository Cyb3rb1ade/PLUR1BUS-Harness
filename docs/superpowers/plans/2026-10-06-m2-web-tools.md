# M2 `web.fetch` / `web.search` with SSRF protection — Implementation Plan

**Goal:** Ship the harness-native `web.fetch` and `web.search` tools (D94, D95) as pure library code under
`packages/core/src/tools/web/`, with the SSRF guard (D94 "Safety") as the centrepiece, the one-round tool-call
repair hook (D97 item 1) and the capability-index rows (D103) for both tools. M2 acceptance 12 (SSRF suite part),
13 (`no-provider`, normalised results, provider interface) and 14 (repair → `tool-call-invalid`).

D109 policy classification (the index only carries `effect: external`).

## Design

Dependency-free (Node built-ins only). Every network hop goes through one function, `guardedRequest`:

1. parse the URL (`http:`/`https:` only, no userinfo);
2. if the host is an IP literal, classify it (all legacy IPv4 spellings, IPv6, IPv4-mapped/compatible, NAT64, 6to4);
   otherwise resolve **all** A/AAAA records through an injectable resolver and refuse if **any** answer is not public;
3. connect to the **pinned** address (a `lookup` that can only return it, so the TCP connect cannot be re-resolved —
   no DNS rebinding) while Host header, SNI and certificate checks keep the hostname;
4. stream the body through a decompressor with a byte cap and a total deadline;
5. on a redirect, go back to 1 for the new URL (max 10 hops).

Private ranges are refused by default; the only exception is an explicit per-installation CIDR allowlist (D94).

## Files

| File | Purpose |
|---|---|
| `src/tools/web/ip.ts` | IPv4/IPv6 parsing (legacy notations), range table, `classifyAddress` |
| `src/tools/web/guard.ts` | `Resolver`, `AddressPolicy` (allowlist), `resolveGuarded` |
| `src/tools/web/failure.ts` | typed failures with `hint` + `userAction` |
| `src/tools/web/http.ts` | `guardedRequest`: pinned connect, redirects, size/time caps, decompression cap |
| `src/tools/web/html.ts` | HTML → readable Markdown (no deps), boilerplate removal, entities, sections |
| `src/tools/web/robots.ts` | robots.txt parser, per-host pacer (fake-clock injectable) |
| `src/tools/web/fetch.ts` | `web.fetch` pipeline: content-type allowlist, charset, extraction, sections + cursor, provenance |
| `src/tools/web/search.ts` | `SearchProvider`, `SearchService` (fallback order, normalisation, provenance, `no-provider`) |
| `src/tools/web/tools.ts` | tool specs (JSON Schema, `effect: external`) and capability-index rows |
| `src/tools/repair.ts` | schema validation + one structured repair round → `tool-call-invalid` |
| `test/tools/web/*.test.ts` | one test file per module, local stub servers and stub resolvers only |
