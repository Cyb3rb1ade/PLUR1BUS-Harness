# E2 plan: i18n completeness check (de/en)

Branch `chore/i18n-check`, one PR. Scope: `scripts/check-i18n.mjs`, its config/allowlist, tests, lint wiring.

## Findings from the survey (main @ 8eae9d4d)

- The only de/en message tables in the repo are the desktop shell's `apps/desktop/ui/src/i18n/{en,de}.json` (149 keys each, in sync, placeholders equal).
- CLI messages (clap help, Rust errors) are English-only strings in Rust with no catalogue; the tray menu has a small Rust-side de/en match in `apps/desktop/src-tauri/src/tray.rs`. Neither is a table the script can compare; documented as an open point, not guessed at.
- `apps/desktop/**` is off limits for this package (parallel work), so gaps found there are allowlisted with a reason, not fixed.

## Design

1. Surfaces are registered in `scripts/check-i18n.config.json` (catalogue dir + source dirs). Any other directory holding `en.json` + `de.json` fails as `unregistered-catalogue`, so a new table cannot dodge the check.
2. Checks: missing key either side, blank/non-string value, `{name}` placeholder multiset equality, dead keys (literal use, or template use such as `` `pair.error.${x}` `` / `` `settings.${p}Title` ``), hardcoded text outside the tables (textContent/placeholder/title/alt assignments, aria-label via setAttribute, createTextNode, `element(tag, class, "literal")`, inline `de ? "..." : "..."` ternaries, HTML text nodes/attributes).
3. Allowlist entries (per key or per file) require a `reason`; an entry that matches nothing fails as `stale-allow`.
4. Comments are blanked before scanning so commented-out code neither counts as use nor as hardcoded text.
5. Wired into `pnpm lint`; tests in `scripts/check-i18n.test.mjs` build temp-dir fixtures, no repo files touched.

## Rulings

- Heuristic errs toward reporting (fail closed); cost of a false positive is one allowlist line.
- en == de text (e.g. "Version", "Updates") is legitimate, not a finding.
- No CI workflow change; `pnpm lint` already runs in CI.
