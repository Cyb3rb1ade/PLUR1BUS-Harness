# D5: user documentation (quickstart and operations manual), en and de

Branch `docs/user-quickstart`. One PR. Docs and one checker script only; no product code.

## Goal

`docs/user/en/{quickstart,operations}.md` and `docs/user/de/{quickstart,operations}.md`, written for a person who
installs and runs the harness, not for a developer of it. Every command line and every path in them is backed by the
code or by the generated `docs/cli.md`. Anything that does not exist yet is labelled as planned, never described as
working.

## Sources (the only ones the text may rest on)

- `docs/cli.md` (generated from clap) for commands, flags and which commands are still stubs.
- `crates/plur1bus/src/paths.rs` for the home and its subdirectories; `service/{mod,systemd,launchd,schtasks}.rs`
  for the unit names and locations; `output.rs` for exit codes; `install/setup.rs` for the nine setup steps and the
  two questions; `scripts/install/install.{sh,ps1}` for installer locations and variables.
- `docs/rpc.md` (error codes), `skills/plur1bus-ops/` (check ids, repair steps, crash reasons; kept fresh by a test),
  `docs/reboot-survival.md`, `docs/manual-release.md`, `docs/module-guide.md` §12.
- A real run: a source build in a temp home (`daemon start`, `daemon status`, `agent create`, `config set --dry-run`,
  `1staid check`, `1staid bundle`, `daemon stop`, the failure messages with no daemon). Output quoted in the docs is
  copied from that run.

## Tasks

1. Plan (this file), first commit.
2. `scripts/check-docs-commands.mjs` + `scripts/check-docs-commands.test.mjs`, test first. The script
   - parses `docs/cli.md` into a command tree (headings `## \`plur1bus ...\``) with each command's options, the global
     options, and the set of stub commands (help text ends with a milestone label such as `— M2`);
   - extracts every `plur1bus ...` command from fenced blocks and inline code in `docs/user/**/*.md`;
   - fails on an unknown subcommand, an unknown flag, or a stub command used without the marker `# planned`;
   - fails on a `<home>/<dir>` path whose first segment appears nowhere in `crates/` or `packages/*/src`;
   - exits 1 with `file:line` diagnostics; `--self-test`-free, no dependencies, no network.
3. Wire it into `pnpm docs:check` (one `&&` clause) and into the `lint` script's `node --test` list.
4. Write the four documents, plus `docs/user/README.md` as an index. English first, German as a faithful translation
   (same structure, same commands and paths; only prose differs).
5. Run the checker over the new docs, then `pnpm docs:check`, `pnpm lint`, `pnpm typecheck`; run `pnpm test` for the
   touched scripts.
6. PR with: Problem, Design, table "acceptance criterion -> test", Rulings, Open points.

## Acceptance criteria

| # | Criterion | Check |
|---|---|---|
| A1 | Every `plur1bus ...` line in `docs/user/**` names a real command and real flags | `check-docs-commands.mjs`, test cases for unknown command, unknown flag |
| A2 | A stub command (login, channel, project, uninstall) is never presented as working | checker rejects it without `# planned`; test case |
| A3 | Every `<home>/...` path exists in the code | checker; test case with an invented directory |
| A4 | en and de contain the same commands in the same order | checker compares the extracted command lists of each pair; test case |
| A5 | The checker runs in CI | part of `pnpm docs:check` |

## Rulings (conservative defaults, marked `RULING` in the script where they live in code)

- A command inside a doc that is not in `docs/cli.md` fails the check, even when it is only illustrative; examples
  that are deliberately wrong must be written without the `plur1bus` prefix.
- The guide does not promise that a packaged release is published. It describes the installer and the feed it reads,
  and a build from source that was run for this PR.
- Where the code and an older doc disagree (the check count in `docs/operations.md`), the code wins and the older doc
  is left alone; it is listed in the PR's open points.
