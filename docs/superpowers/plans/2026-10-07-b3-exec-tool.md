# B3 — Shell-Ausführungswerkzeug mit Sandbox-Stufen (Plan)

Ziel: `packages/core/src/tools/exec/**`, Werkzeug `exec.run`. Reine Bibliothek (Tool-Spec wie `tools/web`), keine neue RPC-Methode, daher kein RBAC-Umbau.

## Design
- Eingabe: `program` + `args[]` (nie ein Shell-String; `shell:false`), `cwd`, `env`, `timeoutMs`, `maxOutputBytes`.
- `cwd` wird über `canonicalisePath` (D109-Pfadschicht) in die freigegebenen Wurzeln aufgelöst; außerhalb = Ablehnung.
- Umgebung: nur Allowlist-Namen; nichts Geerbtes außer Allowlist, geheimnisartige Namen nie.
- Stufen `deny` (Default) / `ask` / `allowlist`; jede Ausführung läuft durch `decide()` (Capability `shell.exec`, Flag `shellAllowlisted`), Rückfrage über `ApprovalPort`.
- Audit: eine Zeile vor der Ausführung (Entscheidung; schlägt das Schreiben fehl, läuft nichts) und eine Ergebniszeile; keine Argument- oder Env-Werte.
- `ProcessPort` (Spawn, Prozessbaum beenden: POSIX Prozessgruppe, Windows `taskkill /T /F` über einen Runner) und `TimerPort` sind Ports; Tests nutzen Fakes, plus ein echter POSIX-Smoke-Test.

## Tests
Argument-Injection, Env-Leak, Timeout, Prozessbaum-Aufräumen, Ausgabe-Truncation, deny als Default, cwd-Wurzel, Audit, Approval, Policy-Deny.
