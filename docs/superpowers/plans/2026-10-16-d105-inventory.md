# D105 runtime decisions and evidence

Builds on Draft #536, normally merged from `codex/d103-p1-live-index`. No D106 gate changes.

## Inventory and decisions

The pure triage, distributions, escalation and boundary helper already existed. Composition and context sizing each ran the synchronous rule classifier. This phase adds a bounded message runtime and a real `modelRoles.decision` call through the same provider router, auth, privacy pin, billing rule, budget and usage measurement as foreground calls. The decision role receives only the current message as JSON data and the stable category prefix; it gets no tools, recalled memory or session excerpts.

One decision per foreground message; context sizing reserves across configured class profiles without making a classification call. `chat`, unavailable decision role, invalid replies and timeouts use the agent's default profile with the core discovery surface only. The core set currently consists of scoped `capabilities.search` when available. Summarization and the internal decision call remain tool-less.

`MessageTriage` holds class/effort while a trusted `taskBoundary.atBoundary=false` is active. The provider also freezes the resolved profile, so editing a class table cannot switch an active task. Followups retain the preceding class. New tasks apply the new recommendation. Multi-task messages use the highest recommended class for the serial turn; separate delegation is not implemented here.

`triage/classes.defaults.json` owns the family/class table. Deployment profile names are read at task boundaries from `<home>/model-class-profiles.json`, falling back to live `decision.classProfiles`; unknown/malformed mappings fall back to default/core-only. The selected profile remains fixed across tool rounds and repairs. Reasoning effort is preserved in the task decision/telemetry; provider adapters currently have no normalized reasoning-effort request field, so this phase does not claim vendor effort enforcement.

## Named acceptance tests

- `one decision per message; task class and effort remain fixed until an explicit boundary`.
- `timeout and malformed decisions fall back to default/core-only; turn cancellation still aborts`.
- `provider fallback/chat uses agent default with only core search, never task shortlist or class profile`.
- `class profiles reload at task boundaries without switching an active task`.
- `configured decision role invokes router once per message with no tools and keeps budget accounting`.
- `D103 system: install, update and disable between RPC turns without restarting the core` now uses a separate configured decision-role replay, preserving cross-phase integration.
- Missing/non-array decisions now use the documented validation error. The baseline segmentation regex uses a fixed whitespace lookbehind to avoid quadratic backtracking; the existing 200k-character and generative span tests remain active. Two previously TODO cases become normal passing tests without changing their assertions.

## Eval evidence

Dedicated `test/fixtures/triage-message/gold.json` contains 72 distinct English/German messages (single, multi, dependencies, chat) with gold spans/categories/minimum classes. `recordings.json` captures the deterministic baseline classifier replies on 2026-10-16; these are not vendor-model recordings. The gold and replay files are separate; the runner never reads gold to form a prediction. An all-chat wrong classifier fails the gate.

Recorded baseline: 72 messages, 86 gold tasks, exact-span segmentation F1 1.0, under-provisioning 0.0, category matches 85/86 (verified by the evaluator). `evaluateMessages` gates at at least 60 messages, F1 >= 0.9 and under-provisioning <= 0.05. The test reports actual denominators; the exact counts in the PR validation supersede a hand-written summary.

Live evaluation is explicitly opt-in via `PLUR1BUS_LIVE_TRIAGE_EVAL=1` and an explicit `PLUR1BUS_TRIAGE_CLASSIFIER_MODULE`. Without opt-in only this new live test is skipped. No model was contacted for quality/latency acceptance; no CI or Nightly was polled. Deployment of the live port in a nightly runner remains owner work.

## Threats

| Attack/failure | Protection | Test |
| --- | --- | --- |
| Message asks the decision role to run tools | Dedicated internal role has no tools and no transcript/recall | configured decision role… |
| Malformed spans, dependencies or probabilities steer routing | Structured validation, recalculated class, fallback | timeout and malformed decisions…; existing classifier validation suite |
| Timeout or decision budget/auth failure aborts ordinary message | Default/core-only fallback, caller abort still propagates | timeout…; provider fallback/chat… |
| Reclassification or hot-edited mapping changes an active task | Hold class, effort and resolved profile until boundary | one decision…; class profiles reload… |
| Self-fulfilling eval | Gold separate from replay; deliberately wrong classifier must fail | recorded baseline reaches… |
