# M2 budgets (L8) — plan

**Goal.** M2 acceptance 10 (`docs/milestones.md`): *"L8: budget checked before every model call; a breach refuses rather than truncates silently."* ADR-010 §4 (budgets enforced in code, not in prompts, per agent and per user/project) and ADR-005 (no secrets or content in stores). This package delivers the core-side accounting and enforcement library plus `budget.status|set` over RPC and `plur1bus budget status|set`. The provider adapters (built in parallel) will call `recordUsage` and `check`; until then only the interface and fake events exist.

**Out of scope.** Per-project and per-user budgets (M5/M4), per-turn/per-session ceilings, per-zone allocation, retry budgets (prompt builder / scheduler), voice budgets (D110), dreaming's own cap (ADR-009 Q1: measure first). No notification schema addition: soft warnings go to an injectable event sink (core wires it to the logger).

## Design

- `packages/core/src/budget/` (new, self-contained; imports only `node:*`):
  - `period.ts` — `periodBounds(ts, timeZone, "day"|"month")`: start/end instants and key of the local calendar period, DST-safe (binary search over the zone's local date, no offset arithmetic); `validateTimeZone`.
  - `prices.ts` — versioned price book (data, no live call): `PriceTable { version, effectiveFrom, models }`, append-only; `PriceBook.at(ts)` picks the newest table effective at the **event's** time; `costMicros(prices, usage)` in integer micro-USD.
  - `store.ts` — `node:sqlite` database `state/budget.sqlite`, `PRAGMA user_version` migrations, WAL + `busy_timeout`. Tables: `usage_event` (append-only ledger: agent, provider, model, four token counts, `cost_micros` and `price_version` fixed at record time, optional unique `request_id` for idempotency — **no content column**), `budget_limit`, `settings` (time zone), `soft_notice` (one soft warning per limit and period).
  - `service.ts` — `recordUsage(event)`, `check(agent, model, estimate)` (+ `enforce`, throws `BudgetExceededError`), `status()`, `setLimit`/`clearLimit`/`setTimeZone`.
- Aggregation is query-time over the ledger, so a time-zone change re-buckets history consistently and concurrent writers cannot lose updates (every write is a single `INSERT`; no read-modify-write).
- RPC (additive, `x-since 1.5.0`, experimental, `x-server: core`): `budget.status`, `budget.set`. `budget.set` is forbidden over WebMCP (like every config-writing method).
- CLI: `plur1bus budget status [--agent] [--json]`, `plur1bus budget set (--global|--agent A) --period day|month --metric cost|tokens [--soft N] [--hard N] [--clear]` and `--timezone ZONE`; cost values in USD with ≤ 6 decimals.
- Core wiring: one new block in `core.ts` (service opened at start, closed at stop, `buildMethods` gets `budget`).

## Rulings (defaults, fail closed)

1. Metric `tokens` = input + output (cache tokens are priced, not counted against token limits).
2. A hard cost limit with a model that has no price in the effective table **refuses** (`unpriced-model`); token limits still work.
3. Default time zone `UTC` until `budget set --timezone`; period = local calendar day / month.
4. Hard limit: refuse when `used + estimate > hard` (a call landing exactly on the limit is allowed). Soft: warn once per limit and period when `used + estimate > soft`.
5. `check` is advisory against concurrent in-flight calls (no reservation); the overshoot is bounded by the in-flight estimates.
6. Idempotency: an event with a `requestId` already recorded is ignored (`recorded: false`).
