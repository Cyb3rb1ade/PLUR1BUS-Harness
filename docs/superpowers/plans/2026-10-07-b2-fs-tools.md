# B2 — File tools (`file.read|write|list|stat`) with path policy

Code: `packages/core/src/tools/fs/`. Tests: `packages/core/test/tools/fs/`. Hand-written doc: `docs/fs-tools.md`.

## Problem
Agents need to read and write files, but only inside roots the owner granted. Every path must pass the D109 path policy
(`policy/paths.ts`, used, not changed), and the tools must survive symlink escapes, `..`, Windows drive/UNC forms,
check-then-use races, huge files, devices and half-written output.

## Design
- `createFsTools({ roots, deny?, cwd?, limits? })` → `{ tools, index }`, same shape as `createWebTools` (dispatcher takes it;
  nothing registers itself). B1 (tool registry) is not on `main`: the tool spec type is local (`FsToolSpec`, effect `read` |
  `local-write` from D109 §2) and structurally compatible. Dependency named in the PR.
- Path in → `canonicalisePath` (roots, deny, access) → typed refusal or real target. Open only via `openVerified`
  (`O_NOFOLLOW`, dev/ino/birth re-check, parent re-check). Never a raw `open(path)`.
- `file.stat`: metadata of the real target (identity re-checked after `stat`).
- `file.list`: directory entries (no link following, deny-listed names hidden, sorted, `maxEntries`, scan cap → fail closed).
- `file.read`: `O_NONBLOCK` open (a FIFO cannot hang), `fstat` on the opened handle: regular files only, size limit, then
  text/binary decision (NUL byte or invalid UTF-8 ⇒ binary). Binary is only returned with `encoding: "base64"`.
- `file.write`: size limit before any I/O; temp file in the target's directory (`O_EXCL`, via `openVerified`), `fsync`,
  re-canonicalise the target, identity unchanged, then `rename` (overwrite) or `link`+`unlink` (create-only, no clobber).
  Temp removed on every failure. Parent directory must exist (no implicit mkdir).
- Results carry `rootId` + root-relative `/`-separated path, never the host absolute path.

## Rulings (conservative, fail closed; `// RULING:` in code)
1. Relative paths resolve against `cwd`, default the first root.
2. Binary content is refused unless `encoding: "base64"`; a read whose size exceeds `maxReadBytes` without an explicit
   `length` is refused, not truncated.
3. Created files `0600`; overwrite preserves the existing permission bits (POSIX only).
4. No implicit `mkdir -p`; overwrite is opt-in (`overwrite: true`).
5. Directories with more than 10 000 entries are refused for `file.list`.
6. A ranged read starting mid-codepoint is treated as binary.

## Tests (red team)
Symlink escape (file, dir, dangling), `..`, absolute outside, Windows drive/UNC/device/ADS syntax (pure, any OS), swap race
(leaf replaced by link between check and open; parent replaced), oversize read/write, FIFO and device files, hard link,
case-insensitive deny hit (+ real case-insensitive FS on macOS/Windows), binary vs text, atomic write (no partial file on
failure, temp cleaned), create-only no-clobber, abort.
