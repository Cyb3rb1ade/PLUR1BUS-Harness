# E2: i18n completeness check (de/en)

**Problem.** The web UI has de/en catalogues (`packages/web/src/i18n.ts`); nothing checks that they stay in step,
that placeholders match, that no key is dead, or that no user text is hard-coded next to them. The CLI has no
catalogue at all: its messages are English literals in `crates/plur1bus/src/**` (`git grep` confirms no locale code).

**Design.** `scripts/check-i18n.mjs [--root <dir>]` reads `scripts/i18n.config.json` (catalogue files, source dirs,
allowlist path) and checks, per catalogue file: (1) key sets of `en` and `de` equal, (2) `{placeholder}` sets equal per
key, (3) no dead key (a key never referenced as a string literal outside the catalogue), (4) no `t("x")` with an unknown
key, (5) heuristic: text literals in `h(...)` children and `aria-label|title|placeholder|alt` props outside the
catalogue, minus `scripts/i18n-allowlist.json`. An unparseable catalogue line fails closed. Wired into `pnpm lint`
(unit test `scripts/check-i18n.test.mjs` with fixture trees).

**Rulings.** CLI: no catalogue exists, so there is nothing to check; adding a second `catalogues[]` entry later covers it.
Not translating Rust messages is out of scope. Heuristic hits are fixed by moving text into the catalogue or, for
brand/non-language text, by allowlisting `file` + `text`.
