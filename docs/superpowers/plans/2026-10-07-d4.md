# D4 plan: `logs.query`, `logs.tail`, `logs.tail.stop` (core RPC for the log view)

Spec: `docs/superpowers/specs/2026-10-01-logging-and-diagnostics-design.md` (D111 §2.9 "Log viewer", §2.3 attribution R7, §4 redaction, §8 test 12), `docs/log-schema.md`.
Package: `packages/core/src/logs/**`. Branch `feat/logs-query-rpc`, one PR.

## Problem

The web and desktop log views need to read `logs/` through the core, not the files. The files are written by several processes (supervisor, core,
modules), rotated by size (`<file>` newest, `<file>.1` ... `<file>.<keep>` oldest), may end in a half line while a writer is mid-append, may contain
corrupt lines, and can be large. The foundation writer (redaction at write time, `ts`/`source` shape) is not on `main` yet: the lines on disk today are
the legacy `{ at, level, role, ...fields, msg }` shape with no redaction.

## Design

* `files.ts` lists `logs/` (regular files only, `lstat` + open-then-`fstat`, never a symlink) and groups `<role>.log[.n]`, `<role>.out.log[.n]` and
  `audit.log[.n]`. `payload.log` is never exposed.
* `reverse-reader.ts` reads one file backwards in 64 KiB blocks (no full read), drops a trailing fragment without newline, strips `\r`, discards lines over
  256 KiB (counted as corrupt) without buffering them. `seek.ts` bisects by byte offset for the first line at or after a timestamp, so a cursor or `until`
  does not rescan the file.
* `normalize.ts` turns a line into one wire record: D111 shape (`ts`, `source`) or legacy (`at` ISO or epoch ms, `role`), audit lines (`at`, `action`,
  `actor`). Unknown legacy keys move into `attrs`. Anything unparsable is a corrupt line: counted, never fatal.
* `redact.ts` applies the D111 §4 rules from the `@plur1bus/log-schema` data (key, pattern, url, deny-path, optional pii, plus the core's own known secret
  values) to every string and key of the record before it leaves the process. It is idempotent on already redacted text. Text search runs on the
  redacted text only (no oracle for removed secrets).
* `query.ts`: k-way merge over the per-role chains, newest first. Order key `(ts, role, line hash)`, so a cursor (opaque, base64url of that key) stays valid
  across appends and rotations. Filters: `since`, `until`, `levelMin`, `components` (source keys), `text`, `stream`. `limit` 1..1000 (default 100).
  Result reports `corruptLines` and `scannedBytes`; a hard scan budget per call (default 64 MiB) ends with `truncated: true` and a usable cursor.
* `tail.ts`: polling tailer (injected clock and timer), per file `{identity, offset, carry}`. Rotation (identity change or shrink): the remainder of the
  renamed file is read first, then the new file from 0. Only complete lines are consumed. Notification `logs.lines` carries `tailId`, records,
  `corruptLines`, `dropped`. Bounded: at most 4 tails, ttl default 5 min and at most 1 h, 1000 records per poll (older ones counted in `dropped`), 1 MiB per
  file per poll. `logs.tail.stop` and core shutdown end tails.
* RBAC: new policy action `logs.query` (Owner/Admin only) for all three methods, in `RPC_RULES`, `policy.ts`, the matrix fixture, guard-test params and
  `docs/rbac.md`.

## Tasks (test first, small commits)

1. Plan (this file).
2. reverse reader + seek: half line, CRLF, oversize, block boundaries, empty file, big file reads bounded bytes.
3. normalize + redact: legacy and D111 shapes, corrupt lines, log-schema redaction vectors, idempotence, secret registry.
4. query: filters, merge order across roles and rotated files, cursor stability across append and rotation, scan budget.
5. tail: rotation mid-tail, partial line completion, ttl, limits, stop, shutdown.
6. RPC schema + methods + RBAC + core wiring + docs; `pnpm prep`, lint, typecheck, docs:check.

## Rulings (also marked `// RULING:` in code and listed in the PR)

R1 own policy action `logs.query` (Owner/Admin) instead of `logs.read` (which includes Operator and Viewer): raw log text is wider than the operator's
page view; fail closed. R2 reader-side redaction in addition to the writer's (the writer is not on main). R3 file attribution wins over a line's own
`source` (D111 R7); a mismatch is flagged `attributed: false`. R4 `payload.log` is never readable here. R5 tail delivery rides `events.subscribe`
(`names: ["logs.lines"]`, opt-in); notifications are broadcast to every subscriber of that name, so a `tailId` selects a client's own tail; `events.subscribe` itself is not
RBAC-gated (open point: needs per-connection delivery in module-api). R6 text search is a case-insensitive substring over redacted text (no regex).
