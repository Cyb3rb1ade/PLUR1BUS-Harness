## After and named checks

- SQLite FTS5, canonical SHA-256 row hashes, local vector identity/hash cache. `restart preserves row hashes; FTS queries are literals; cached vectors invalidate only on changed rows`.
- Core-owned service and shutdown; skills refreshed at every turn and on folder changes; supervisor read-only `ext.watch` plus authoritative `ext.list` refresh. `D103 system: install, update and disable between RPC turns without restarting the core`; `supervisor skill snapshot enforces effective agents and fails closed after disconnect`.
- Per-agent blocked/pinned skills; optional common-registry discovery metadata for plugin commands/channel actions. `human discovery metadata wins; plugin commands and channel actions reuse the common registry`.
- Admission remains separate: persisted rows never supply executable tools. MCP visibility derives from the current registry; unconditional policy refusals are filtered before ranking. Argument-dependent roots/classification/approvals still run at dispatch. `agent views do not expose another agent MCP registration or blocked skill, even from persisted rows`.
- Dispatcher-only `capabilities.search` adds discovered allowed tools to the following model round. Search uses unweighted discovery ranking. `capabilities.search expands a missed tool only through dispatcher and scoped registry`.
- Ready local engine embedding only; no download/probe/cloud adapter initiated by the index; lexical fallback and current Doctor snapshot. `local vectors are persisted and reused; no cloud adapter is admitted`; `without a ready local model FTS continues and Doctor reports the degraded mode`.
- Nightly 03:00 host-local system job `capabilities.recheck`, registered in the existing ledger; fresh stats calibrate bounded priors. `nightly recheck uses the system-job contract and removes orphaned skills`.
- Owner refinement: default values live in `toolcall/calibration.defaults.json`, installation override `<home>/capability-calibration.json`, reloaded on recheck. Minimum 10 effective offers, per-agent data with same-name/kind/version global fallback, symmetric −0.2/+0.2 bounds, 14-day half-life in hourly UTC buckets, resets on version change/removal. Historic pre-migration counters have no timestamps and do not train the decayed prior. `calibration uses file defaults, symmetric caps, global fallback, decay and update reset with fixed clock`; `negative prior lowers shortlist rank but search retains the tool; positive global prior cannot cross policy`.
