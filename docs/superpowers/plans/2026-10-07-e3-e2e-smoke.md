# E3 — End-to-end smoke: CLI → daemon → core on a fresh home

## Problem
Every system test drives one subsystem. Nothing walks the shortest user path end to end on a clean home
(daemon, agent, one chat turn, backup, restore elsewhere, clean stop).

## Design
`tests/e2e/smoke.test.ts` reuses `tests/system/helpers.ts` (BIN, `cli`, `startDaemon`, `reapHome`) — the repo's
existing harness for a real binary. Steps: fresh temp home → `1staid check` (no daemon) → `agent create` →
`daemon start` (fake chat provider via the env guard) → `daemon status` → `memory add` → `chat` (session create +
submit) and a second turn → `backup create` → `backup verify` → `daemon stop` → `backup restore` into a second temp
home → daemon on the restored home sees the agent, the memory and (when archived) the session → stop.
`finally` always stops both daemons and SIGKILLs anything still naming either `--home`.

## Rulings
- There is no `plur1bus init`; a home is materialised by its first write (`agent create`). The test starts from an
  empty directory and asserts that, instead of inventing a command.
- `setup` is not used: it downloads Node (live network).
- There is no `session create/submit` CLI; `chat` is create+submit over `session.*` RPC and is what is exercised.
- Windows: skipped (POSIX `pgrep` reaper, same as all system tests); analysed only.
