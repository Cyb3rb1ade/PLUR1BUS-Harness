# D2 — Plugin catalogue: signed index fetch (plan, 2026-10-07)

Spec: `docs/superpowers/specs/2026-09-27-extensions-ecosystem-design.md` §7.2, §7.2.1, §8.1, §8.5. Code: `packages/core/src/catalog/ext-index/`.

## Scope
Fetch the catalogue index (`index.json` + detached signature) through an **egress port**, verify an Ed25519 signature
(`node:crypto`) against public keys **from configuration** (none built in), refuse a lower `serial` (rollback), keep an
offline cache that expires, and report every failure as a typed `ExtIndexError`.

## Not in scope
Package download/install (X4), revocation application, config-schema keys, RPC/CLI surface, the D1 catalogue browser.

## Ports (D1/B4 are not on main)
- `EgressPort.get(url, { maxBytes, timeoutMs, signal })` — the egress policy (B4) lives behind it.
- `IndexCacheStore` — filesystem implementation (`extensions/catalog/`), atomic writes.
- `now()` clock — tests use a fake clock, no sleeps.

## Test list
valid signature · invalid signature · wrong key · tampered entry · replay of an old index · equal serial different bytes ·
expired fresh fetch · cache stale after `expires` · offline fallback · tampered cache · malformed shapes · size cap ·
key from config only · fake HTTP server end to end.
