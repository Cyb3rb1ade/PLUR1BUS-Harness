# V1 Outbound A2A Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; verify each behavior through a failing regression and a passing implementation.

**Goal:** Reach explicitly trusted A2A peers from the existing collaboration tools through the complete D109, privacy, egress, budget and audit boundaries.

**Architecture:** Keep the single delegation target port. A private peer registry holds pending/trusted public-key pins. A transport dispatches every HTTP request as `network.a2a`, then applies per-hop egress/DNS pinning, privacy and byte/deadline bounds. Peer/turn budgets live in the budget module. Owner-only RPC manages peers; no Rust CLI logic is added.

**Tech Stack:** Node 24.21.0, TypeScript, existing A2A SDK 1.3.0, node:crypto/node:sqlite/node:http. No new dependencies.

**Spec:** Work package V-A supplied by the owner on 2026-10-31 and the subsequent instruction to start V1 directly after R-2b's TypeScript PR.

## Global Constraints

- Order: R-2b TypeScript #835, then V1; the Rust CLI is independent and Claude-owned. MM/U/#820 remain separate.
- Main now uses RPC 1.10.0 for #837, superseding the initial #820 reservation. R-2b uses 1.11.0; V1 uses 1.12.0 (no open competing claim found).
- Each a2aClient config key has explicit x-restart/x-tier; default disabled.
- Ed25519 verification is mandatory; no unapproved TOFU or implicit key rotation.
- Headless approvals are denied; existing D109 approval/attestation/RPC surfaces suffice, no new UI.
- Never log card/message content, tokens or key material. Extend leak tests without weakening assertions.
- Rust source changes are limited to mechanical RPC fixtures/roundtrip requirements. No rebase, amend, force push, merge or CI polling.

## Review Focus

- A signed card with a wrong/rotated key or an ambiguous JSON-RPC endpoint fails before any message is sent.
- Every redirect rechecks the pinned address and localOnly; credentials and message bodies never follow a cross-origin redirect.
- Removing a peer during admission cancels future/in-flight requests and cannot resurrect a trusted record.
- Concurrent calls cannot exceed peer/turn call and token ceilings; unavailable budget/audit services refuse sends.
- Nonhuman/Admin callers cannot pin peers; direct collaboration calls cannot manufacture surface/headless context.
