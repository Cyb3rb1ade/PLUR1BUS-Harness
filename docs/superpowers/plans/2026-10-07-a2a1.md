# A2A1: Agent Card and task endpoints (local, loopback, inbound only)

Authority: ADR-008 §A2A (+ amendment 2026-09-27), ADR-007 (RBAC), `docs/milestones.md` M6. Code: `packages/core/src/a2a/`.

## Scope
Inbound only. No outbound call (no card fetch, no client). Server is off by default: nothing in `core.ts` starts it; a
caller builds `createA2aHandler` / `startA2aServer` explicitly. No RPC method, no config-schema key, no new dependency.

## Design
- `handler.ts`: transport-neutral `(A2aHttpRequest) -> A2aHttpResponse`. Routes `GET /a2a/<agent>/.well-known/agent-card.json`
  and `POST /a2a/<agent>/` (JSON-RPC 2.0: `message/send`, `tasks/get`, `tasks/cancel`).
- `server.ts`: node:http adapter, loopback bind only, Host check, body cap enforced while reading.
- `policy.ts`: the `a2a-peer` principal (`Bearer` key, sha256 compared in constant time) and `authorizePeer`
  (deny by default: peer must list the agent AND the action; agent must have opted in).
- `tasks.ts`: bounded in-memory task store + runner over the existing `ChatProvider` seam, one AbortController per task.
- `rate.ts`: token buckets (per peer, per remote address for failed auth), injected clock.
- Limits: body 1 MiB, text 64 KiB, 60 req/min/peer, 8 live tasks/peer, task retention TTL, reply timeout.

## Tests (test-first)
card schema + content-free; lifecycle with `FakeChatProvider` (submitted/working/completed/failed/canceled);
unauthenticated / wrong key / unlisted agent / unlisted action / cross-peer task isolation; size, rate, batch, content-type limits;
loopback-only bind; audit lines.
