## Behavior / Verhalten

`composition/embedding-policy.ts` decides, before engine construction, which provider block `buildEngineConfig` passes
to the engine. `local-transformers` (or no provider) keeps the pinned local defaults exactly as before.

Embedding, any other provider id (`openai`, `openrouter`, `cohere`, `jina`, `voyage`, `google`, `openai-compatible`,
self-hosted `ollama`/`tei`/`vllm`/… or any other id) goes to the engine's OpenAI-compatible client unchanged, with:

- `model` and `dimensions` (positive integer) required — the vector space is always explicit;
- `apiKeyEnv` required: the name of the environment variable holding the key. A plaintext `apiKey` is refused
  (`reason: secret-in-config`), as is a `baseUrl` with credentials in it;
- `baseUrl` required except for `openai` (without it the engine calls api.openai.com); http(s) only. The spelling
  `baseURL` is refused because the engine ignores it and would call its default endpoint;
- `fallback` refused (`reason: embedding-fallback-refused`): no silent second model;
- a non-loopback endpoint needs `memory.embedding.privacyAck` for exactly that provider and endpoint (existing
  `privacyAcknowledgmentError`, function `text`, `E_DENIED`). Loopback (`localhost`, `127.0.0.0/8`, `::1`) needs none.

Reranker: `cohere` is accepted with `apiKeyEnv`; it stays mandatory (`enabled: true`) with `fallbackProvider: disabled`.
A custom `baseUrl` is refused (the engine calls the Cohere endpoint itself and would ignore it). Every other remote
reranker id fails with `E_NOT_AVAILABLE`, `reason: engine-adapter-factory-unavailable`, and is not replaced by another model.

Missing or malformed details fail with `E_INVALID_PARAMS` (`reason: engine-provider-config-incomplete` or
`engine-provider-invalid`). Licence confirmation for pinned non-commercial models stays with `checkEngineConfigLicences`.

## Threat table / Bedrohungstabelle

| Attack / failure | Protection | Test |
| --- | --- | --- |
| Key written into config.json or logs | `apiKey` and URL credentials refused; only `apiKeyEnv` | engine-config: secret-in-config cases |
| Text sent off the machine without consent | `memory.embedding.privacyAck` bound to provider and endpoint | engine-config: privacy acknowledgment cases |
| Explicit model silently changes vector space | `fallback` refused; model and dimensions required; unsupported reranker fails visibly | fallback and adapter cases |
| Typo routes to the default OpenAI endpoint | `baseUrl` required for non-openai ids; `baseURL` refused | baseUrl cases |
| Test seam used for production adapters | no test-internals changes | source review of bindEngine and pinned engine |

## Follow-up 2026-10-18: "Nur lokal", reranker consent, egress at start (stacked PR feat/local-only-privacy)

Owner decision (Christian, 18.10.): "Nur lokal" soll es geben; cloud providers stay fully supported with their privacy
acknowledgment; engine calls to cloud providers go through the harness egress rules.

- `privacy.localOnly` (basic tier, `x-restart: core`, Owner/Admin, audited) plus `agents.<id>.privacy.localOnly`
  (override in both directions) and `privacy.localEndpoints` (exact origins of self-hosted model servers that count as
  local). Local = loopback or listed; a LAN address is never local by itself. Refusal: `E_DENIED`, `reason: local-only`,
  with a hint to the switch; never a silent switch to another model. One decision module: `privacy/local-only.ts`.
- Enforced in: embedding and reranker (`embedding-policy.ts`), engine LLM features with their own transport, chat and role
  routing incl. compaction summaries (`composition/provider.ts`), discovery (`locked: "local-only"`, listed not hidden;
  Models page shows a badge), voice (local tier only, no cloud adapter built), media generation, media index and
  captioning (shared: pinned while any agent is local-only), doctor report (`privacy.local-only` fails while cloud models
  are configured), Settings > Privacy (de/en).
- `memory.reranker.privacyAck` (same shape as `memory.embedding.privacyAck`): the Cohere reranker needs it, bound to the
  provider (the engine fixes the endpoint).
- Egress at start: `checkEngineEgress` judges every engine model endpoint with `egress.decide` before the engine is built;
  a refusal fails the start with `E_DENIED`, `reason: egress-denied`. `egress.request` gained a POST-capable variant
  (method, headers, capped body, no redirects with body/headers) for the later engine fetch port.
