# D106 phase 3 handoff — remaining named host tools (Draft)

Builds on #525, normally merged after refreshing origin/main. The apps.open capability change intentionally tightens catalogue pins: sys.read/low -> apps.launch/local-write/medium, approval at T2, once ceiling. hostctl.app.open shares that floor. Existing tests were updated to assert the stronger declaration, not relaxed to accept both.

## Inventory

Added sys.memory, sys.startupItems, sys.services, sys.updates, apps.focus, apps.quit, pkg.upgrade. Registered tools use classifyHostTool for canonical filesystem arguments, roots, deny precedence and hostile environment names. OS subprocesses use phase-2 sandbox HostExec. Output is bounded and redacted; absent services fail explicitly. App ids are a closed grammar, never arbitrary script source. quit requests graceful close; forced close is unavailable.

D106 names versus shipped surfaces: file.read/write/list/stat; hostctl.fs.search/edit/mkdir/copy/move/trash; exec.run and hostctl.proc.* sessions; proc.info is inspect and proc.kill accepts a signal; sys.* plus the four additions; pkg.* plus upgrade plan; apps.* plus focus/quit; clipboard.* and notify. Canonical fs.delete and PTY shell.session.open/send/read/close **are not implemented**; hostctl pipes are not PTYs. No full spec-name parity claim. sys.startupItems is the **one explicit camel-case spelling** accepted by the tool registry to match D106; other non-lowercase names remain rejected.

pkg.upgrade returns an exact dry-run plan, matching existing install/remove. It does not perform a package change. Name validation rejects option and command injection. system update reports never install or refresh caches. Linux reporter currently supports apt only; Windows startup reporting covers Startup folder only (not Run registry keys/scheduled tasks). Each result states coverage.

## Decisions and behaviour

apps.launch always asks; capability never grants above once. sys.read continues read-only. apps.quit uses proc.signal and approval even if unsaved state cannot be determined. Existing exec refuses sudo/doas/pkexec/su/runas/gsudo; expect/sshpass now refused too. Hostctl blocks SUDO_*/SSH_ASKPASS and named password/elevation programs. No T3 elevation implementation or password transport is introduced. Arbitrarily encoded interpreter programs are not semantically inspected; unsandboxed owner bypass remains unsafe by definition.
