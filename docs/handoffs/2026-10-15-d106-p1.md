# D106 phase 1 handoff — sandbox core (Draft, incomplete)

Base: origin/main 6e2beb9e. #508 remains open; exec and approval internals are untouched.

## Inventory and decisions

`tools/sandbox` exports `sandboxSpawn(argv, policy, {signal})`, typed policy/detection/results, canonical roots and deny precedence. A Rust exec-only launcher uses existing libc; no npm dependency or new crate. CPU/process/core limits precede the target; POSIX process groups are killed and drained. Resources report configured bounds and duration, **not measured CPU/RSS**. No shell is inserted. Egress requests become `none` with an explicit warning. All backends are partial or unavailable, never strong.

Seatbelt: default deny, exact roots, explicit credential path/name denies, no fork permission, fixed OS runtime read paths; stdout/stderr bounded. `sandbox-exec` is deprecated and a deliberate dependency. Darwin rejects RLIMIT_AS; a 100ms RSS watchdog terminates the single-process target, with transient overshoot possible. This is not a kernel memory limit.

Linux: bubblewrap namespaces and read-only roots, static credential masks. Write roots are refused because mount masks cannot protect names created after launch. Backend probe tests user-namespace availability. Per-process RLIMIT_AS/CPU/NPROC is not an aggregate cgroup limit.

Windows: unavailable and fail-closed. Repository search found no existing Job Object implementation (supervisor_children.rs explicitly documents its absence). taskkill is not a security backend. No restricted-token claim is made.

Doctor exposes `tools.sandbox` with partial/missing reason and installation hint. Helper delivery is not integrated into release archives; installed builds report it missing until installed at `<home>/bin/plur1bus-sandbox-limits`.
