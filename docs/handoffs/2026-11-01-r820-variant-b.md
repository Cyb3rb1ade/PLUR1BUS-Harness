# PR #820: Variant B; native coding grants deferred to K2a

Variant B keeps ACP agents, ACP terminal callbacks and connector probes unavailable
on macOS and Windows. They refuse with `sandbox-unavailable` before launching a
process. A platform override cannot enable ACP on an unsupported host. Installed
connector discovery may still report executable and login-file metadata, but it
reports the protocol as `unprobed` and never opens credential contents.

Linux retains the existing bubblewrap opt-in for exactly one Harness-provisioned
worktree under `state/worktrees`. The opaque grant pins a live database row,
canonical path, directory identity and Git metadata. Every sandbox preparation
rechecks the row, symlink-free ancestry, exact writable root and hardlink scan.
Git metadata stays read-only. Other writable Linux policies remain refused.
The existing real connector argv gate remains closed pending credential-bind
acceptance; this change does not enable vendor CLI processes.

## UID0 refusal and historical root evidence

ACP under UID0 is unsupported: the kernel task probe reports `not-enforced`, so
the production launcher refuses with `sandbox-unavailable` before target spawn.
The bubblewrap backend also requires a positive, valid namespace task cap for ACP,
and the native helper independently refuses UID0 in `--tasks-required` mode with
`sandbox-unavailable` (exit 125) before exec. Ordinary tools retain their separate
best-effort task-cap behavior.

The historical additional root run reported 11/16 passing: the ACP-start cases
stopped because UID0 task enforcement was unavailable. This is not a supported-user
functional acceptance result or a merge blocker. The independent a44 re-review
also ran as root without bubblewrap and initially without a built helper; its
backend failures cannot establish normal-user containment. Supported Linux
acceptance uses a normal user with bubblewrap and a built helper under `CI=1`.

The focused UID0 regression uses a normal user's real bubblewrap namespace with
`--uid 0 --gid 0 --cap-drop ALL`; it verifies `id -u` is zero, then proves required
mode exits 125 without creating the target marker. The old helper executed the
marker command with exit 0. This tests UID0 inside a namespace, not a privileged
host-root installation. The ordinary bubblewrap path retains the normal user's
UID and is covered by the existing real launch tests. Final actual-root container
acceptance belongs to the controller after the source freeze.
