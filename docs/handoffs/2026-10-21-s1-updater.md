# GP5 S1: v2-only desktop updater without zip

Stand: 21.10.2026. Owner selected variant 3: retain exactly `tauri-plugin-updater =2.13.0`, disable its optional `zip` feature and publish only v2 updater artifacts. No plugin fork or Tauri major upgrade.

## Artifact prerequisite

Owner confirmed that no desktop feed or GitHub release has been published, no existing desktop clients use v1 artifacts, and committed release keys are placeholders. The configured feed host did not resolve during inspection. Repository inspection found no Windows/Linux updater ZIP or tar.gz artifacts: desktop CI builds unsigned dmg/exe/deb/rpm/AppImage packages, the default/variant configs disable updater artifacts, and `tauri.release.conf.json` enables v2 artifacts with `createUpdaterArtifacts: true`. Harness CLI/core tar.gz payloads and macOS packaging ZIPs are separate from this desktop updater manifest. The Host-Addons checkout contains no desktop updater manifest.

The publisher now rejects Windows/Linux `.zip` and `.tar.gz` URLs before hashing `latest.json`, including mixed-case/encoded extensions, query strings and fragments. Malformed Windows/Linux URLs fail closed. macOS `.app.tar.gz` remains supported. This is also necessary on Linux: plugin 2.13.0 gates legacy AppImage tar.gz extraction behind the feature named `zip`; with that feature disabled it expects raw AppImage bytes.

## Dependency and policy changes

Only `rustls-tls` remains enabled on the exactly pinned plugin. `cargo update --manifest-path apps/desktop/Cargo.toml -p tauri-plugin-updater --precise 2.13.0` removed zip 4.6.1 and its now-unused dependencies. Cargo also normalized compatible Windows dependency edges without introducing a new crate version. The three zip advisory exceptions were removed from `audit-allowlist.json` and the dependency policy. Attribution was regenerated on macOS arm64.

No updater product logic changed: signature verification in `Update::download`, installation of exactly those downloaded bytes, anti-rollback and the exclusive install slot remain intact. Store builds remain without the direct updater.

## Validation and integration

The feed regression tests were run red before implementing the rejection: three failures and one valid-v2 control passed. They then passed. A locked Cargo metadata regression checks the entire desktop dependency graph, all features and targets, for absence of any `zip` package. The original zip-upgrade TODO was turned into this executable no-parser qualification; the two existing native signature/install-slot qualification TODOs remain visible and are not claimed as completed native acceptance.

`cargo tree --locked --offline --manifest-path apps/desktop/Cargo.toml --all-features --target all -i zip` returns the expected `package ID specification zip did not match any packages`. There is no zip entry in the desktop lockfile.

The first complete audit after exception removal reported six unrelated blocking findings: RUSTSEC-2026-0381/-0382/-0383 in both Cargo workspaces, already fixed by open Controller PR #670 (`fix/webpki-advisories`, `3ea7b5e64baaf7aebc4ae8518aee88f3afbd5d6d`). S1 is stacked on that prerequisite instead of duplicating its patch bumps. Root/pnpm Engine pins are unchanged by S1; root Cargo security updates belong to the prerequisite. Desktop lockfile change is intentional.
