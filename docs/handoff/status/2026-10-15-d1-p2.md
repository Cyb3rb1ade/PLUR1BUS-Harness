# D1 phase 2 — WP13 packaging and installer surfaces

2026-10-15. Branch `codex/d1-p2-packaging`, stacked on Draft #498. Implementation exists; native acceptance remains open. No CI status was queried.

## Inventory and decisions

- Explicit native build/staging scripts separate online/offline, beta/dev/stable and direct/Store/Flatpak. Tauri resources map directly to `apple/`, `cli/`, `image/`, `models/`; immutable build-time bundle metadata matches the payload. Payload provenance records checksums, size, target, fixture status and signing mode. Large payload hashes stream.
- macOS app+DMG use environment-selected signing identity or ad-hoc. NSIS uses the pinned Tauri 2.12 template with D101 initial options, silent opt-outs and exact ownership markers. OS uninstall preserves application data. MSIX is staged/packed through Windows SDK MakeAppx, not an unsupported Tauri bundle target; StartupTask, desktop7 shortcut, scheme and file association are explicit. Store and Flatpak are online-only and built without updater features. Flatpak uses the existing GNOME Background portal and deliberately avoids the AppIndicator loader unavailable in GNOME runtime.
- Apple pkg is an embedded resource: checksum, pkgutil trust and exact Team ID precede fixed `open -W`, detection and `container system start --enable-kernel-install`. No sudo or pkg download. Vendor selection/HTTPS URL/checksum come from trusted bundle metadata. Consent precedes download; download is bounded, redirects refused, checksum (and optional Windows signer thumbprint) verified before interactive launch. No silent vendor arguments.
- CLI shim copies a checked host release artifact, checks digest and marker on both install/remove, refuses any foreign file/path and adds a marked PATH entry once. The actual root CLI still lacks the planned `target.json` forwarding contract; copying is implemented, forwarding acceptance is a KNOWN GAP.
- Fixed native shortcut controls appear in Advanced on Windows/AppImage. AppImage refreshes only enabled owned menu/autostart entries after a move; a missing entry stays absent. Flatpak shows actual portal grant through existing Runtime settings. Foreign shortcut/Run/PATH entries are preserved.
- Install-runtime, Advanced and three-tier uninstall screens have DE/EN, bounded error copy, licence consent, focus/keyboard behavior and actual progress. App-only preserves data; Everything rechecks exact `plur1bus-state` in Rust. RecoveryFailed evidence is retained rather than purged. Summary shows unknown byte sizes honestly where no usage probe exists.
- Artwork exports use existing icon masters as a documented fallback for unavailable canvas exports; no fabricated Store screenshots. No new runtime dependencies in phase 2. Build channel selects the initial feed channel without replacing saved user preferences; dev uses a debug bundle and is refused as a release channel.

## Threats

| Attack | Protection | Evidence |
|---|---|---|
| Renderer-supplied installer URL/argv | Closed requests; fixed vendor and native command adapters; trusted embedded metadata only | Installer/closed-input tests |
| Tampered pkg/download | SHA-256, exact Apple trust/Team-ID, optional Windows Authenticode; never execute failed input | Wrong hash/signature and no-sudo/no-silent tests |
| Foreign CLI or PATH substitution | No-clobber copy, digest ownership marker, regular-file/ancestor checks, exact marked PATH edit | Collision, modified digest, symlink and idempotent PATH tests |
| Malicious offline resource path | Relative component allowlist, regular file and non-symlink components; loaded digest checked before create | Controller offline/wrong-digest tests |
| Destructive uninstall request | Closed tier enum and exact typed confirmation before mutation; controller object ownership and recovery checks | AppOnly and Everything tests |
| Update recreates deleted shortcut | Initial-choice marker; ordinary upgrade detection preserved through flag parsing; missing shortcut not recreated | Injectable ownership/update tests; NSIS native execution still open |
| Raw runtime error leaks secrets | Fixed error classifications, existing diagnostics/redaction sink reused | Arbitrary-error UI test; no raw subprocess output displayed |

## Behavior and conflict hotspots

Wizard offers runtime assistance when none is detected; consent is separate from harness installation. Advanced adds CLI, diagnostics, shortcut and uninstall controls. Signing/staging do not install system software. Changes touch bundle metadata/build.rs, Tauri config/ACL, controller uninstall, install helpers, shell IPC and UI/i18n. Reconcile concurrent M3/M4 pairing/CLI contracts at their owning interfaces; no policy or engine changes were made.

## Validation and remaining acceptance

Ad-hoc app signature and installed bundle scheme/resource locations inspected. This does not validate Apple installer, real model weights, actual image bootstrap or forwarding.

Focused backend install/config/controller tests, UI install/i18n/browser keyboard+axe checks, format/staging tests and debug/release Clippy results are recorded with the PR. Full desktop Rust suite: 489 passing, zero failed, six existing opt-in ignored; final focused install/controller/config/integration/update regression suites pass. Final full desktop UI suite: 110 passing, zero failed, four existing TODOs; root lint passes including 99 tooling tests. The broad root `pnpm test` encountered an open-handle hang after successful Recurring UI tests and was bounded by terminating that test subprocess; it is not a passing run.

KNOWN GAP todos: native Windows NSIS/MSIX compile/install/upgrade/uninstall; Linux deb/rpm/AppImage/Flatpak native install/portal and moved-path acceptance; actual signed Apple pkg and vendor metadata; full default-model offline payload acceptance; Store identity/publisher, listings/signing credentials; native host forwarding contract; genuine screenreader passes. Windows Store login startup controls require the authoritative StartupTask state API; the UI explains Windows Settings → Apps → Startup and direct HKCU changes are refused. Package screenshots and size probes remain explicit release/UX follow-ups. No real keychain, runtime installation, data deletion, notarization or publication was used for tests.
