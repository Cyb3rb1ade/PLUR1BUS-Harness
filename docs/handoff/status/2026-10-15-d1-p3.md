# D1 phase 3 — real-image compatibility and migration safety

2026-10-15. Branch `codex/d1-p3-real-image`, builds on Draft #501. **D1 is not yet acceptance-ready.** The actual M8 image is the integration source; synthetic WP8/WP11 tests remain separate evidence.

## Inventory, decisions and behavior

The desktop state layout is reconciled with `containers/harness`: `PLUR1BUS_HOME=/state`, the existing owned state volume at `/state`, and the existing owned model-cache volume at `/state/models`. Volume names and existing data are preserved; files are not moved/copied from an assumed native installation.

Read-only upgrade compatibility preflight checks the old image's CLI snapshot/verify/restore and smoke contracts before stopping or mutating it. A missing contract refuses the operation; the running installation is preserved. A dedicated immutable-image probe starts only isolated labelled test resources, checks real daemon readiness and reports the actual CLI contract inventory. It never creates a device/user, changes authentication, opens a real keychain or prints runtime environments. The non-gating `desktop-real-image.yml` builds the existing M8 Dockerfile and publishes only a redacted compatibility report; it does not push an image or use PR secrets.

## Store migration and rollback

**KNOWN GAP: production native/stub→real and image→image store migration is not implemented/accepted by this phase.** Missing authoritative contracts above prevent a safe integrated transaction. Existing WP11 journal/fault-injection tests prove the synthetic state machine only, including crash rollback; they are not relabelled as a real-store SIGKILL test.

Reuse the existing M8 `backup create` (running core stages LanceDB and SQLite through their owning snapshot APIs), `backup verify`, and stopped-core `backup restore` archive mechanism for the eventual native import. Native updater snapshots intentionally omit memory and must not substitute for that archive. Never copy live LanceDB/SQLite with Rust filesystem operations. The concrete migration implementation should restore a verified archive into a new owned staging volume, retain source and verified archive, keep a private durable outer journal, and switch the active volume only after the authenticated full gate. A crash before commit must leave the original selected; an interrupted staging volume must be quarantined/retried. The existing per-unit restore's ordinary error rollback does not establish whole-transaction SIGKILL recovery. API/session state coverage and cross-image schema rules need owning-workstream validation before enabling this flow.

## Native identity/location — proposal only

Owner proposal: native installer/updater owns `native-install.json` beside the established host `target.json` in the user PLUR1BUS configuration directory (proposed Unix `~/.config/plur1bus/`, Windows `%APPDATA%\PLUR1BUS\`; owner must ratify platform locations). Closed versioned content: `version:1`, random `installationId`, absolute `binaryPath`, absolute `stateRoot`, `platform`, `arch`, public `binarySha256`. No token/certificate/credential. Parent/file 0700/0600; Windows user+SYSTEM DACL, no symlink/reparse ancestors, atomic replacement and directory sync. Only native installer/updater writes it; uninstall removes only a matching identity. Desktop must validate it against live authenticated installation identity and never overwrite that binary with a shim. Owner must settle coexistence and stale/uninstalled records. **No file, registration or new identity contract was implemented.**
