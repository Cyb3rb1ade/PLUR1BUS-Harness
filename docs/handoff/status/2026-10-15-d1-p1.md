  shell pull/navigation commands; startup argv and the actual singleton callback
  use one dispatcher. macOS `RunEvent::Opened` supplies scheme/file opens.
- `tauri.conf.json`: desktop `plur1bus` scheme and `.p1x` Viewer association.
  The exact `tauri-plugin-deep-link =2.5.0` is the only new direct dependency.
  Its lockfile adds its platform/INI transitive dependencies; existing direct pins stay fixed.
- `commands.rs`, `client.rs`: confirmed native offer provenance, origin-bound
  leaf/CA trust, fresh connection only, explicit retry after failure. No pin field
  is accepted from a manually edited pairing form. Successful pairing consumes
  the offer; dismissing/pulling the next intent drops it.
- `spa.rs`: only the current connection's existing SPA can navigate, through its
  existing proxy origin with a validated hash route. No connection is opened or
  selected by the link, and no ticket is issued by this command.
- `ui/src/shell.ts`, `views/add-remote.ts`, `ipc.ts`, EN/DE catalogues:
  origin prominently shown, optional fingerprint shown, readonly origin/code
  prefill, explicit Submit, keyboard focus, unavailable chat/install/file hooks.
  No extension lookup, file read, package install or chat submission occurs.

## Decisions

The current brief brings WP12 into D1 despite historical D2 wording. Chat keeps
its unavailable hook: forwarding is optional in the brief, and shell links do not
create chat activity. Catalogue IDs accept a single name or `publisher/name`,
including the specification's `plur1bus/zabbix-triage`; never a file or web URL.
Percent-encoded query values are decoded once to support normal encoded origins
and paths. Malformed, nested, non-ASCII and control escapes are refused. Unknown
or duplicate parameters, authority/userinfo/ports on the custom scheme, traversal,
query/fragment navigation and oversized input are refused before normalization.

Tauri CLI reads `plugins.deep-link.desktop` for installed-bundle registration
independently of the runtime plugin. The plugin's default runtime is deliberately
not initialized: it broadcasts raw URL events and its debug argv handler logs
foreign URLs. Native OS events and the singleton callback instead feed the guarded
shell mailbox, with argument-free pending notifications. Scheme registration for
portable AppImage and exported Flatpak metadata is completed with phase 2 packaging.

## Threat table

| Attack | Protection | Evidence |
| --- | --- | --- |
| Pairing phishing or automatic replacement | Visible origin; explicit submission; fresh UUID; no repair ID for links | Pairing browser test and real Store preservation test |
| Certificate substitution | Native offer bound to exact origin/code; TLS pin checked before redeem; CA fetched by hash | TLS link pin/CA tests; existing generated-certificate suite |
| Open foreign host, API/auth path or traversal | Strict path segments and SPA route allowlist; current live connection checked again in Rust | Open refusal table; mutation corpus; native SPA predicate |
| Ambiguous/oversized input | 4096-byte link bound, ASCII, single decoding, closed query, 16 pending intents | Parser rejection and bounded inbox tests |
| Sensitive link/code in diagnostics | Typed `desktop.deeplink.ignored` event with empty attributes; no raw plugin runtime events | Fixed-log regression; D111 sink tests |
| Malicious `.p1x` file | No file opened or read; only unavailable confirmation | Nonexistent path/file URL hook regression |
| Lost early launch event | Install listener then pull pending intent; bounded native mailbox | Browser handshake and native fixture |

## Validation and limits

Local platform: macOS arm64, Node 24.21.0, pnpm 10.28.0, Rust 1.95.
The parser and inbox tests, explicit malformed-input table and deterministic
single-byte mutation corpus exercise real production parsing. Browser tests use
an injected native transport and disposable Chromium profile: explicit pairing,
failed request then explicit retry, unavailable hooks, WCAG AA, keyboard focus and
reflow at 400/960/1440/2560 in DE/EN × light/dark. Generated certificates and
MemoryStore exercise TLS and persistence without real credentials.

Exact final test results and native singleton outcome are recorded below after
completion. Windows/Linux native installation, OS-open file association, manual
VoiceOver/NVDA/Orca and a packaged live SPA navigation remain unverified locally;
no automated Chromium pass is substituted for those human/native checks. No CI
status was polled. No real keychain, personal harness, runtime objects or services
were used by tests.
