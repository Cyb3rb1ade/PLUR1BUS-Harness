## Owner follow-up implemented — 2026-10-18

**RSA is agent-only in v1.** Direct RSA file authentication is removed from v1;
new keys stay Ed25519. The refusal is `rsa-direct-unsupported`, with the DE action
hint “Lade den Key in deinen SSH-Agent oder erzeuge einen ed25519-Key.” WP3 must
translate this reason (EN: “Load the key into your SSH agent or generate an
ed25519 key.”), show it before passphrase/decryption, and never fall back to direct
RSA. The research direct-key path uses the tested guard; production/UI wiring
remains in WP1/WP3, not delivered by this S0 executable.

**Verified:** `node apps/desktop/scripts/ssh-rsa-agent-spike.mjs` starts an isolated
OpenSSH 10.5 sshd and agent, generates a temporary 3072-bit RSA identity externally,
loads it with `ssh-add`, and runs the Rust probe. Both **rsa-sha2-256 and
rsa-sha2-512 authenticate and execute a fixed command successfully**. The Rust
probe reads only public host/identity files and the fixture agent socket; the
OpenSSH agent performs the private signatures. All services/files belong to this
fixture and are closed/deleted in `finally`; personal SSH state is untouched.
The server's host key is Ed25519; RSA-only server-host-key verification is not
claimed by this probe. The earlier all-Rust fixture's agent still proves Ed25519.

`cargo metadata --locked --offline` plus the graph regression proves **no `rsa`
crate anywhere in the desktop workspace**, including public-operation dependencies.
`cargo tree --locked --manifest-path apps/desktop/Cargo.toml -i rsa` reports no
matching package. `russh` defaults and its `rsa` feature are disabled; only `ring`
is enabled. `authenticate_publickey_with` delegates to `AgentClient::auth_sign`;
it does not take a private key. Upstream `helpers.rs::sign_with_hash_alg` compiles
the direct RSA signing arm out when that feature is absent. The research guard
refuses every direct RSA algorithm/hash form, while Ed25519/ECDSA remain accepted.
Host/identity matching compares public key data, ignoring mutable OpenSSH comments.
**No advisory/public-operation exception or exception proposal is needed or added.**

Direct RSA may return only with a Marvin-safe version or an audit-compliant
backend. Its named TODO is now a **later feature, not a v1 acceptance gate**.
Five other v1 TODO gates remain; this does not declare all of S0 complete.

Current main `56744c72f` (including #590) was merged normally in `57fc18f0a`,
without rebase/force push. The latest full desktop cargo-audit still reports
