`tiny-keccak` (SFTP map hash generation) declares CC0-1.0, already allowed by
`docs/dependency-policy.md`. Root `deny.toml` is aligned with that existing license
policy. This is a license-policy alignment, not an advisory exception.

`cargo audit 0.22.2` on a throwaway RSA-candidate manifest reports
**RUSTSEC-2023-0071** for `rsa 0.10.0-rc.18`. The
[RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2023-0071.html)
explicitly has no patched versions. Merely using `ring` does not remove that
dependency when the RSA feature is enabled. The owner rule permits no exception
for a maintained crate, so WP1 cannot begin with direct RSA enabled.

The committed ring-only spike graph passes all four `cargo deny check` categories:
advisories, bans, licenses and sources. Duplicate-version warnings remain visible.
`cargo audit` scans the **whole desktop lockfile**, which still reports 7 existing
vulnerability records in `rustls 0.23.45` and `zip 4.6.1`,
plus existing informational findings; the whole-workspace cargo-deny also fails.
These are not fixed by a green spike-only graph. #590 owns coordinated repairs;
this phase adds no allowlist entry and does not claim the full audit green.
The final lock comparison preserves every pre-existing `(name, version)` resolution
from main; unintended intermediate QUIC downgrades were restored before commit.

Audit reproduction uses the same current RustSec database for both candidates:

```sh
cargo deny --locked --manifest-path apps/desktop/transport-spike/Cargo.toml check
cargo deny --locked --manifest-path apps/desktop/Cargo.toml check advisories
cargo audit --file apps/desktop/Cargo.lock
```

The initial cargo-audit network fetch failed locally. Re-running with `--no-fetch
--db <cargo-deny's freshly fetched advisory-db checkout>` produced the results

candidate, create a temporary Cargo project outside this repository, depend on
`russh =0.64.1` with defaults off and `features=["ring","rsa"]`, generate its
lockfile and run cargo-audit on that file. Do not enable RSA in the desktop lock.

## Measured protocol results

Fixture: real embedded `russh` SSH server plus SFTP-v3 handler on ephemeral
loopback sockets, macOS arm64, Rust 1.95, release profile. Generated credentials
stay in memory; no personal SSH agent/keychain/config is used.

| Check | Result |
|---|---|
| Changed host key | Refused before any authentication callback; count remains zero |
| Password / wrong password | Accepted / rejected |
| Ed25519 / ECDSA P-256 | Both logins accepted |
| Encrypted OpenSSH Ed25519 | Wrong passphrase rejected; correct passphrase decodes and authenticates |
| Agent | Generated identity loaded into isolated Unix-socket test agent; signing authenticates |
| known_hosts | Public entry lookup and unknown-host refusal; file stays byte-identical during reads |
| Exec | Separate stdout/stderr, exact exit status 7 |
| PTY | SSH PTY request accepted; does not prove sudo or an OS terminal |
| Upload | 52,428,800 bytes (50 MiB); server digest plus complete SFTP readback match |

| Metric | Release fixture observation |
|---|---:|
| Connection + password authentication, 20 samples, median | 1.355 ms |
| Connection + password authentication, p95 (nearest-rank) | 1.712 ms |
| Upload time | 0.390 s |
| Upload throughput | 128.275 MiB/s |
| Research executable with transport | 5,245,456 bytes |
| Same executable without default features | 431,232 bytes |
| Standalone executable delta | 4,814,224 bytes |

The size delta includes the fixture/client/server and measures this standalone
research executable. **Installed desktop binary delta remains unmeasured**; no
app linkage or five-target size claim follows from these numbers. These are
loopback observations, not LAN or installation acceptance.

**Transfer decision: SFTP**, pending the remaining acceptance gates. Explicit
offsets support a resumable protocol and do not require parsing shell prompts or
running the legacy SCP protocol. WP1 must implement resume/checksum behavior;
this spike only proves transfer and integrity. The preferred in-process tunnel
shape stays planned; proxy HTTP/SSE/WS and jump-host checks remain unproven.
