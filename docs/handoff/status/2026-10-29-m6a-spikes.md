### Five Criteria Evaluation

1. **One card and one endpoint per agent (`/a2a/<agent>/`) on a single HTTP server**:
   `DefaultRequestHandler` and `JsonRpcTransportHandler` are lightweight per-agent state holders with no HTTP listener coupling. A single `node:http` server (or `packages/api` route entry) dispatches `/a2a/<agent>/.well-known/agent-card.json`, `/.well-known/agent-card.json` (for `defaultAgentId`), and `POST /a2a/<agent>` across arbitrary configured agents.
2. **Custom `TaskStore` and `AgentExecutor` without `express`**:
   `@a2a-js/sdk/server` has zero `express` imports (`express` is isolated to `@a2a-js/sdk/server/express`, which is never imported or installed). Custom `TaskStore` (`load`, `save`, `list`) and `AgentExecutor` (`execute`, `cancelTask`) plug directly into `DefaultRequestHandler`.
3. **`JsonRpcTransportHandler` on `node:http` with SSE backpressure**:
   `JsonRpcTransportHandler.handle(body, callContext)` returns either a JSON-RPC response object or an `AsyncGenerator` of JSON-RPC stream responses. Pulling the first iterator item before `res.writeHead(200, SSE_HEADERS)` surfaces synchronous validation errors as JSON-RPC error responses; subsequent chunks are serialized with `formatSSEEvent` and written with `res.write()` + `once(res, "drain")` backpressure control.
4. **`legacyCompat` (`0.3` opt-in, default off)**:
   `ServerCallContext` defaults missing `A2A-Version` headers to `"0.3"` per the A2A 1.0 specification. Calling `validateVersion(callContext.requestedVersion, card, "JSONRPC")` before dispatch rejects missing or `0.3` headers with `VersionNotSupportedError` (`-32009`) when `legacy03` is `false`. When `legacy03` is `true`, `duplicateInterfacesForLegacy(card.supportedInterfaces, ["JSONRPC"])` advertises `"0.3"` alongside `"1.0"` and `LegacyJsonRpcTransportHandler` from `@a2a-js/sdk/compat/v0_3/server` translates v0.3 dotted methods (`message/send`, `message/stream`, `tasks/get`, `tasks/cancel`, `tasks/resubscribe`) to the same `DefaultRequestHandler`.
5. **Extension declarations and extension methods (closes Federation S0, point 1)**:
   `AgentCard.capabilities.extensions` and `ServerCallContext` (`requestedExtensions`, `addActivatedExtension`, `activatedExtensions` → `A2A-Extensions` response header) are native in `@a2a-js/sdk`. Because `JsonRpcTransportHandler.handle()` has a closed `switch` over the 11 standard A2A methods, extension JSON-RPC methods (`federation/*`) are handled by a small pre-dispatch table in our HTTP wrapper right before `JsonRpcTransportHandler.handle()` on the same `/a2a/<agent>` endpoint, enforcing `ExtensionSupportRequiredError` (`-32008`) when the extension URI is missing from `A2A-Extensions`. No `/federation/v1` fallback endpoint is needed.

### Decision

Use `@a2a-js/sdk@1.3.0` (`@a2a-js/sdk`, `@a2a-js/sdk/server`, `@a2a-js/sdk/client`, `@a2a-js/sdk/errors`, `@a2a-js/sdk/compat/v0_3`, `@a2a-js/sdk/compat/v0_3/server`) behind the harness HTTP wrapper (`packages/api`) for auth, rate limiting, body-size caps, JSON-RPC batch rejection, SSE backpressure, and extension method pre-dispatch, and behind `packages/core`'s egress `request`/`streamResponse` `fetchImpl` adapter on the client side.
