# M5 phase 1 — D104 hand-off format

## Inventory and decisions

Base: origin/main 4557176c. Closed handoff/return/ack JSON schemas, sender-side
one-repair validation, receiver ticket, real store reference checks, structured
board-description/comment-feed cards (DE/EN). No new dependencies or engine
changes. No edits to approvals/grants/policy internals. Use existing CollabError
codes. Fan-out remains off; depth default remains one. Model tiers: cheap,
standard, premium. A UTF-8-byte upper bound is used for the cap.

## Threats

| Attack | Protection | Test |
| --- | --- | --- |
| Forged/foreign/expired/nondelegable/used approval | Chain-backed store lookup and authenticated bindings, audited refusal | collab/handoff.test.ts: forged, foreign, nondelegable, wrong-task, expired and used approvals |
| Authority changed after ack | Recheck at start | revocation between ack and start |
| Infinite sender repair / oversized envelope | One repair; 2,000-token bound | over 2000 tokens; invalid schema repairs once |
| Work starts without acceptance / duplicate execution | Ticket ack and one-start flag | delegate cannot start before ack |
| Peer injection through board | Preact escaped text; no executable grants/roles | web/handoff-card.test.ts and handoff-card-browser.test.ts (Chromium, DE/EN) |
| Memory leak / verifier bypass | No memory or verifier access added in this phase | Phase 2 real-store isolation and Phase 4 external verifier tests remain required |

## Behavior changes

Structured hand-off and return JSON in board descriptions/comments has a readable
card. Contracts fail closed; authority failures cannot be repaired by the sender.
No agent tool is enabled by this foundation phase.

## Owner questions

None blocking. The 2,000-token check uses the stricter UTF-8-byte upper bound rather than a
provider-specific tokenizer; billed usage remains separate. Output schema and
citation requirement are explicit in returnContract. Depth 1 and stateless
external targets follow the supplied defaults.

## Conflict hotspots

New collab/handoff.ts and collab/schemas; projects/card-drawer.ts, projects i18n
and projects.css. Tools composition has not been edited. Future M6 targets
should consume the single DelegationTarget port introduced in M5 phase 2.
