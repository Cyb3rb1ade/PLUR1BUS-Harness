# V1 outbound A2A and the Rust CLI handoff

V1 follows the TypeScript R-2b PR #835 because both change the RPC schema and budget surface. The outbound protocol uses the existing `consult_agent` and `delegate_task` tools and one `DelegationTarget` with `kind: external` and `origin: a2a`. Rust CLI implementation belongs to Claude; this PR adds no CLI command.

## Owner workflow and RPC signatures

The experimental Core methods were added in RPC **1.12.0**. The initial allocation reserved 1.10.0 for #820; main now uses 1.10.0 for cache telemetry #837. R-2b allocated 1.11.0, and V1 uses 1.12.0. All four methods require an authenticated Owner **person**, including listing. Agent principals and Admins are denied. The methods are excluded from WebMCP.

| Planned CLI command | Core RPC and input | Result / schema names |
| --- | --- | --- |
| `plur1bus a2a peer add --id ID --card-url URL --kid KID --public-key-file PATH [--credential-secret NAME]` | `a2a.peer.add({ id, cardUrl, kid, publicKey, credentialSecret? })` | Pending `A2APeer`; `A2aPeerAddParams`, `A2aPeerAddResult` aliases. |
| `plur1bus a2a peer list` | `a2a.peer.list({})` | `{ peers: A2APeer[] }`; `A2aPeerListParams`, `A2aPeerListResult`. |
| `plur1bus a2a peer remove ID` | `a2a.peer.remove({ id })` | `{ id, removed }`; `A2aPeerRemoveParams`, `A2aPeerRemoveResult`. |
| `plur1bus a2a peer trust ID --fingerprint SHA256 --revision REVISION` | `a2a.peer.trust({ id, fingerprint, revision })` | Verified, trusted `A2APeer`; `A2aPeerTrustParams`, `A2aPeerTrustResult`. |

These command spellings/options are a handoff proposal, not installed commands. Shared definitions are `A2APeerId`, `A2APublicKey`, `A2AFingerprint` and `DelegationTargetId`. The public key is the closed public JWK `{ kty: "OKP", crv: "Ed25519", x: "<32-byte unpadded base64url>" }`. Private JWK fields are rejected. `fingerprint` is the RFC 7638 thumbprint, `sha256:` followed by unpadded base64url. `revision` is an opaque compare-and-swap identity, not a timestamp.

The Owner supplies the public JWK and key id through a trusted channel. `add` performs no network request and never trusts a peer. Display the pending fingerprint and require the person's explicit decision before calling `trust`. Trust fetches and verifies the signed A2A 1.0 card through D109, then requires a fresh Owner approval showing the complete canonical endpoint, fingerprint and revision. That approval binds all three and the peer id; a standing network grant cannot replace it. Removal or replacement during either approval invalidates the operation. There is no automatic `jku`/JWKS discovery, key rotation or replacement. A changed key needs remove/add/trust; a changed endpoint needs explicit trust again. Removal is idempotent, aborts in-flight requests and prevents stale trust operations from recreating the peer.

An Owner can assign a trusted target `a2a:<id>` with `project.agent.add`; local `AgentId` remains unchanged. Assignment and execution both require an Owner person, project assignment and `agent.use` rights, including previously stored assignments. The remote target runs without local `AgentScope` authority and opens no local agent memory/session store. D104 delegation requests a real receiver acknowledgement before work. Operation-local aliases replace internal handoff, session, agent, task and project ids; card ids, report-to destinations and approval/grant handles are omitted. Acknowledgements and structured returns must match the foreign alias before the adapter translates the reply binding back. Responses remain untrusted data. A2A cannot receive board-card ownership or serve as an independent local review, including reviews without a card; local ACP targets retain their existing contract.

## Local validation and waiting for trust

Validate before RPC without echoing rejected values:

| Input | Exact rule |
| --- | --- |
| Peer id | `^[a-z][a-z0-9._-]{0,63}$`; target id is `a2a:` plus that id. |
| Credential reference | At most 128 characters, `^a2a/([a-z][a-z0-9._-]{0,63})/[A-Za-z0-9][A-Za-z0-9._@-]*$`; the captured id must equal this peer's id. No provider, other-peer or nested slot is accepted. Store a value using the secret command, never an A2A argument. |
| Card URL | At most 2048 characters; parse with the standard URL parser and require `http:` or `https:`, with no username, password, query or fragment. Send the canonical URL. Admission of the host, port and resolved IP remains Core policy. |
| Key id | 1–128 characters, no U+0000–U+001F or U+007F. |
| Public-key file | One JSON object with **exactly** `kty`, `crv`, `x`, with `kty=OKP`, `crv=Ed25519`, and canonical unpadded base64url `x` decoding to exactly 32 bytes. Reject extra `kid`, `alg`, `use`, private fields, JWKS arrays/objects and PEM. Do not strip fields silently. `--kid` is separate and must match the card's protected signature header; there is no JWK `kid` to reconcile. |
| Fingerprint/revision | Preserve the schema's `A2AFingerprint` format and opaque revision; use the values returned by add/list rather than inventing or deriving a revision. |

Trust can wait for both card-network approval and endpoint trust approval. The Core bounds the whole trust operation by live `a2aClient.timeoutMs` (at most 120 seconds), including waiting, discovery and confirmation. The Rust client must use a per-call timeout of **130 seconds** for this method instead of its normal 30 seconds. Keep this override local to trust. Show progress on stderr in human mode; keep JSON stdout reserved for the final document. The existing `approval.*` flow handles decisions on an available trusted surface. Ctrl+C closes the request connection, propagates cancellation and leaves the peer pending unless trust had already committed; fetch list before retrying if completion was uncertain. Never retry a trust call automatically.

The approval's existing `summary` and `diff` fields carry the same closed public projection of the endpoint, RFC 7638 fingerprint and revision, checked against the action arguments. This makes the complete coordinates visible in ordinary Web and channel prompts. The Web card recognizes only that matching internal-tool projection; other approval text keeps its normal masking. Generic token/path heuristics do not hide these public coordinates (a fingerprint itself resembles a long token). Actual registered or just-leased secrets still make the trust request fail closed in the adapter before any public projection is shown. There is no new RPC field or response shape.

## Output and errors

Human output should show the peer id, target id, card URL, key id, fingerprint, revision, pending/trusted state and whether a credential reference exists. Never display a leased credential or foreign card text. Every command should offer `--json`, print the raw RPC result using the existing output helper, and add only the CLI document discriminator: `a2a.peer.add/1`, `a2a.peer.list/1`, `a2a.peer.remove/1` or `a2a.peer.trust/1`. Failures use `error/1` and the existing structured RPC error.

Use the existing exit mapping: 0 success; 2 invalid input, `E_NOT_AVAILABLE`, approval-required or cancellation; 3 only the existing `E_LOCKED` case; 1 for authentication/authorization refusal, conflict, storage or other RPC/protocol failures. Missing/invalid key files and missing trust arguments fail locally before any RPC. Do not add a new interpretation of these global exit codes.

Every adapter reason has the following mapping; the CLI must not branch on English error text:

| Reason | RPC error | CLI exit |
| --- | --- | --- |
| `denied`, `egress-denied`, `local-only` | `E_DENIED` | 1 |
| `invalid-peer`, `invalid-key` | `E_INVALID_PARAMS` | 2 |
| `peer-exists`, `peer-untrusted`, `peer-revoked` | `E_CONFLICT` | 1 |
| `peer-not-found` | `E_NOT_FOUND` | 1 |
| `approval-required` | `E_APPROVAL_REQUIRED` | 2 |
| `card-signature`, `budget-exceeded`, `request-failed`, `unavailable`, `too-large`, `aborted` | `E_NOT_AVAILABLE` | 2 |

No remote status/error text, credential-bearing URL, message/card content or key bytes are interpolated into errors. Storage/audit failures map to `unavailable`. Removing an unknown valid id returns `{ id, removed: false }`, exits **0** and prints “Peer was already absent” in human mode; JSON preserves `removed: false`. It is not `E_NOT_FOUND`. Authentication failures outside the adapter retain the shared mapping.

## Transport and accounting

`a2aClient.*` is live, advanced, Owner-writable and disabled by default. Every HTTP request, including card discovery and each same-origin GET redirect, is an internal `peer.a2a_http` tool call with effect/capability `network.a2a`. It has the external approval floor and taint restrictions. A headless ask is denied immediately. Approval arguments contain ids, hashes and byte counts. The human reason shows a decoded, redacted preview, bounded after redaction, and carries recurring-job context. Preview text never enters audit fields. Admissions remain per hop: discovery, D104 acceptance and execution have different action bindings and each redirect needs current admission. Broadening one approval across these calls would weaken those bindings.

Every hop requires an **exact** allowlisted hostname or IP before DNS, rechecks the live port policy and pins the socket to its approved IP. A suffix/wildcard entry does not admit A2A, including public peers. Ordinary egress keeps its existing suffix rules. HTTP is limited to explicitly admitted loopback; other peers use HTTPS with normal certificate checks. The A2A-specific purpose permits explicitly listed shared/Tailnet address ranges while ordinary egress retains its private-address restriction. A 100.64/10 address alone is not proof of mesh membership: the exact Owner allowlist, verified peer key and pinned connection remain mandatory. LAN, metadata and mixed private DNS answers remain denied, including the metadata address inside 100.64/10. `privacy.localOnly` additionally requires the actual pin to be loopback or 100.64/10 or fd7a:115c:a1e0::/48. The synthetic trust identity is outside the local agent-name grammar, so an agent privacy override cannot relax global local-only. `privacy.localEndpoints` cannot allow a WAN A2A peer. Cross-origin redirects and all POST redirects are refused. Each response has a byte cap and deadline; compression is refused. Abort/disconnect closes the socket.

Signed cards must identify exactly one same-origin JSON-RPC 1.0 endpoint and verify under the approved Ed25519 key id. Every card and message request sends `A2A-Version: 1.0`. The adapter requests blocking `SendMessage`, accepts completed tasks or agent messages with text, and fails safely on remote errors, interrupted/nonterminal tasks or malformed replies. It does not install remote tools or process remote file URLs.

Local abort stops waiting and closes the connection. It **does not guarantee cancellation of work on the foreign harness**: a blocking response may not have exposed a remote task id yet, and V1 sends no remote `CancelTask`. A remote peer may continue its own work. Cancellation support is a follow-up requiring a known task id and a separately gated, pinned and budgeted request; no cancellation bypass is introduced.

The budget module atomically reserves per-peer and shared-turn HTTP-call and token capacity, persisted across connections and Core restarts. Helpers cannot reset a shared turn's budget. Existing global/user/project/agent/session/turn token limits also apply. A2A has no authoritative billing-token field: communicated UTF-8 request/reply bytes are a conservative token upper bound. This does **not** meter hidden model work performed by a peer. Card reads consume calls but no message tokens. Unknown usage after a write consumes the reserved bound; only a proven unused request is refunded. One content-free `a2a.call` admission audit is written before each outgoing request; normal D109 decision/outcome entries remain separate. An unavailable audit or budget refuses I/O.

Raw per-call reservations are retained for 30 days and compacted at startup and the next admission. Only durable per-person/session/turn/peer call/token totals remain after compaction, so replaying an old turn cannot reset quotas. Cancelled rows contribute nothing; orphan reservations retain their full token bound. These content-free totals remain for the lifetime of the budget database. Do not describe this as deletion of all historical metadata.

Management audit actions are `a2a.peer.added`, `a2a.peer.trusted` and `a2a.peer.removed`; `a2a.card.rejected` records signature or endpoint drift. They contain identifiers and fixed reasons/states, no URLs, key bytes, credentials or card/message text. Management writes record the decision inside their transaction before commit and roll back if audit fails. The audit and peer database are separate stores; an audit decision can remain if the later database commit fails.

Optional bearer credentials are peer-scoped secret-store references validated again immediately before each lease. A human approval preview first obtains a local lease so even a credential's first use can be redacted; a headless or policy-denied call never leases. Otherwise the lease follows egress/privacy admission. It stays registered for redaction, is bounded by the operation deadline and is revoked when that hop ends. Only the reference is stored in the peer database, never its value.

Successful reply and acknowledgement text is redacted before it crosses the target port or reaches transcripts/results. The operation retains its exact leased values until decoding finishes, including rotated and short credentials; known encoded forms are masked as well. Signed card verification and token accounting continue to use the original bytes.

## Required CLI tests

- Exercise all four RPC methods through a fake Core and assert exact closed parameters and method/schema names.
- Check raw `--json` preservation, including additive unknown result fields and each CLI schema discriminator.
- Verify pending-first registration, explicit fingerprint/revision trust, changed-key refusal and idempotent removal; no implicit network approval.
- Reject private/malformed JWK files, credential-bearing URLs, invalid ids and incomplete trust options before RPC.
- Cover the shared exit mappings and fixed errors for denied roles, unavailable Core/peer, approval-required, stale revision and invalid signature.
- Exercise the trust-specific 130-second client timeout, progress, cancellation, complete endpoint display, separate endpoint confirmation and stale confirmation refusal.
- On implementing the CLI, update clap and command dispatch, raw document discriminators, `docs/user/**`, generated `docs/cli.md` and any CLI inventories/help lists in the same PR. Run `pnpm docs:gen` and `pnpm docs:check`; the latter checks command spellings and exits. Proposed commands in this handoff are not evidence that those commands already exist.
- Scan human/JSON/error output for private key bytes, bearer markers, foreign card/message text and remote error markers.

Core regressions live in `packages/core/test/a2a/` (`protocol-leak.test.ts`, `secret-leak.test.ts`, cards and pins), `test/budget/peer.test.ts`, `test/egress/a2a.test.ts`, schema tests and the mechanical Rust RPC fixture roundtrips.
