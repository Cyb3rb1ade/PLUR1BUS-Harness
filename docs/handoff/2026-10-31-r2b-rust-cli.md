# R-2b Rust CLI handoff

The budget service and RPC surface are implemented in TypeScript. The Rust CLI work described here is pending and belongs to a separate PR by a Claude agent. No Rust CLI logic is included in the TypeScript PR.

## Commands and options

- Extend `plur1bus budget set` with `--cache-read-weight <w>`, usable alone or together with the existing limit and `--timezone` options. Accept finite decimal numbers in [0, 1], including explicit zero. Omission preserves the server's active weight; do not send a client-side default. The server rounds to millionths.
- Extend `plur1bus budget status [--agent <ID>]` to display fresh input, cache reads, cache writes, output and counted tokens separately, with the active cache-read weight. Preserve media counts and limits.
- Keep the existing global `--json`, `--home` and `--color` behavior. Do not implement local weighting or read the SQLite store from the CLI.

## RPC and schema names

Source of truth: `packages/rpc-schema/schema/rpc.schema.json`, RPC **1.11.0**. New properties have `x-since: 1.11.0`; the existing methods remain experimental, introduced in 1.5.0, served by Core.

| Command | Method | Schema nodes | Generated Rust types |
| --- | --- | --- | --- |
| `budget set` | `budget.set` | `$defs/methods/budget.set/params` and `/result` | `BudgetSetParams`, `BudgetSetResult` |
| `budget status` | `budget.status` | `$defs/methods/budget.status/params` and `/result` | `BudgetStatusParams`, `BudgetStatusResult` |

`budget.set` gains optional numeric `cacheReadWeight`; its result gains the active weight. Weight-only updates omit `limit`, and their result omits `limit`. Existing limits are returned unchanged. Combined settings update atomically; any rejected setting leaves the complete update unapplied.

`budget.status` gains top-level `cacheReadWeight`. Every period's `total`, every agent's `total` and every model gains `freshInputTokens` and `countedTokens`. Existing raw `inputTokens`, `cacheReadTokens`, `cacheWriteTokens`, `outputTokens`, event/media counts and limits remain present with their existing meanings.

## Output and JSON

For 1,000 input tokens containing 900 cache reads and 50 cache writes, plus 100 output tokens, at weight 0.1, show fresh input **50**, cache read **900**, cache write **50**, output **100**, counted **290**. Raw `inputTokens` stays **1000**. Cache writes retain full weight. Counted totals round once per period/agent/model; do not add already rounded model totals to derive an agent's total.

At weight zero, a weight-only `--json` result on an empty store is:

```json
{"schema":"budget.set/1","timeZone":"UTC","cacheReadWeight":0,"limits":[]}
```

`budget status --json` retains `schema: "budget.status/1"`; its raw RPC value includes `timeZone`, `cacheReadWeight`, `now`, `periods` and `limits`. `now`, period `start` and `end` are RFC 3339 strings. Print the original `serde_json::Value` through `Out::ok`, preserving all fields, including future optional ones; never reserialize through a typed result struct.

New result fields are optional for compatibility with older producers. In human output, label absent breakdown/weight as unavailable or retain the legacy input/output display; never invent zero. Sending the new option to an older Core may return `E_INVALID_PARAMS`; report that error without a silent fallback or a second update.

## Exit codes and errors

Use the existing `Out::from_rpc_error` / `output::exit_code_for` mapping; do not add a separate mapper.

| Exit | Case |
| --- | --- |
| 0 | Successful status or settings update. |
| 2 | Invalid/nonfinite/out-of-range weight, malformed options, an empty update, invalid zone/limit, unsupported method (`E_INVALID_PARAMS` / `E_NOT_AVAILABLE`); retain the existing approval/cancellation mappings. |
| 3 | Existing single-instance lock refusal (`E_LOCKED`). |
| 1 | Unavailable Core, authentication or authorization refusal (`E_UNAUTHORIZED` / `E_DENIED`), RPC/protocol/storage/internal failure, following existing mappings. |

Failure JSON uses `schema: "error/1"` and the existing error/reason envelope. Do not echo arbitrary input or include secrets in diagnostics. Existing budget authorization is unchanged: `budget.set` is human-only and requires `settings.write` (Owner/Admin under current policy), never a WebMCP tool.

## Required tests for the CLI PR

1. Parse weight-only 0, 1 and a fraction; omit the parameter when the option is absent. Accept combinations with existing timezone/limit options. Reject negatives, values above 1, NaN/infinity, missing values and malformed numbers before sending RPC.
2. Capture the actual outgoing `budget.set` params with a test server; no local default, weighting, or second write on errors. Exercise unchanged existing options and limit clearing.
3. Verify human status shows the example's five separate counts and active weight at period/agent/model levels, plus media and limits. Test empty usage and older responses with absent additive fields.
4. Verify `--json` preserves the complete raw response, unknown future fields and the existing schema IDs; failures retain `error/1` and the documented exits 1/2/3.
5. Verify refusal/error paths: older server rejects the new field, Core unavailable, settings-write denied, invalid zone/limit, and mixed update failure leaves all server settings unchanged. Do not skip existing budget tests.
