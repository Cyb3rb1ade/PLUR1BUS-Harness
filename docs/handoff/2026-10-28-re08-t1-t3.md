# RE-08 T1/T3 implementation hand-off

T1 adds RPC 1.7.0 and the engine transport contract. T3 adds the Core-side client,
selection, independent engine identity and guarded reverse-RPC handlers. The Node
implementation remains the default. Selecting the experimental Rust implementation
does not start a process in this package; an absent engine leaves the Core serving,
and recall reports `E_NOT_AVAILABLE` with `reason: engine-unavailable`.

## Compatibility details

- RE-01 remains unchanged. `packages/rpc-schema/src/engine-contract.mjs` derives
  `EngineContract*Data` definitions and operation signatures from that contract;
  the schema tests compare the checked-in projection and check regeneration is
  idempotent. Runtime signals, callbacks and `capture.done` use transport lifecycle
  handling and notifications.
- The existing deprecated Core `engine.event` keeps its payload, metadata and
  opt-in delivery. Its additive `x-engine-notification` annotation describes the
  engine emitter; the generated `EngineTransportEvent` type represents that
  payload. Capability builders and notification validation use the serving role.
- `systemSupplement` returns the contract's `string[]`, and model status uses
  `ModelsStatus`. The brief's other shapes do not match the existing contract.
  Synchronous client readers use values hydrated during connection bootstrap.
- `engine.open` and `engine.agent.close` carry the existing `AgentStore` lifecycle.
  Closing the Core's client closes its connection, not the separately owned engine
  process. `engine.shutdown` is available to the future process supervisor.
- Re-embedding's optional `request`/`id` wire adapters preserve the runtime arguments
  already documented in `packages/core/src/embedding-migrate/engine-port.ts`.
  RE-01's parameterless declarations do not describe these existing arguments.
- Address vectors retain their independent, checked-in provenance. The Python
  generator verifies the added engine addresses and does not generate vectors.
  `Layout::engine_endpoints` supplies the future T4 `RoleKind::Engine` match arm
  without adding the supervisor slot here.

## LLM attribution and the T2 wire requirement

The controller approved the additive outer `agentId` on `host.llm.complete`.
RE-01's `LlmParams` remains unchanged. The wire schema keeps the outer field
optional for compatibility, but the production handler requires a valid, registered,
active Core agent before accessing the completion service. It also requires that
this Core's EngineClient currently owns an open AgentStore or has an in-flight
agent operation/capture for that agent. Closing the last store or completing the
last operation revokes that scope. An ordinary client, a configured but unrelated
agent, and absent/invalid attribution all fail closed; Core never guesses an agent.

T2 must send `{ agentId, params }` for every completion and preserve that attribution
from its actual agent work. Agent-free bootstrap cannot borrow an agent's budget.
T2 authenticates with its current independent `run/engine.token`; Core revalidates
that credential on each reverse call, so a stale connection cannot use a restarted
engine's new work scopes. Closing the reverse RPC connection or stopping Core cancels the provider through
its existing signal; this transport has no separate per-call cancellation frame. A capture's scope lasts until `engine.capture.done`, including
its asynchronous completion rather than only capture acceptance.

The composed provider supplies the same credential leases, egress, per-attempt
budget admission/settlement, retry/fallback, cross-billing refusal and live
`privacy.localOnly` checks as foreground turns. The trusted background identity is
`engine:v1:<agentId>` under the agent's internal scope, with no authenticated person
or approval authority. The internal engine role has an empty tool catalogue and
rejects model-proposed tool calls before dispatch; it cannot acquire D109 rights.
An explicit model names a configured profile or exact configured `provider/model`;
absence uses the agent profile or the composition default. Sampling and token
limits stay per request; stable routers retain their breaker state.

Completion audit records contain agent, internal actor and fixed outcome metadata.
Prompts, completions, credentials and arbitrary provider error text/codes never
enter this boundary's logs, audit or RPC error responses. Budget refusal returns
`E_NOT_AVAILABLE` / `budget-exceeded`; privacy refusal returns `E_DENIED` /
`local-only`. Missing composition remains `E_NOT_AVAILABLE` / `llm-unavailable`.
The existing Node `HostServices.llm` is left absent because RE-01 supplies no agent
attribution there; the explicit Rust reverse-RPC path is bound in Core composition.
