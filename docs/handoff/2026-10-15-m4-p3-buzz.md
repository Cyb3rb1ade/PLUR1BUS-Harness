# M4 phase 3 — Buzz

## Inventory and decisions

New `packages/channels-buzz`: Channel manifest, lifecycle, health, text send, NIP-17/59 crypto, private durable replay claims, normalized public-key allowlist, SecretStore access and pair claim. Core binding, owner/admin audited config and generated fixtures/docs. Existing address-pinned RFC6455 transport now permits an absent Authorization header; voice callers retain their credentials. Host declares cli and all seven channel providers through the pinned engine's public `channels.register`; no engine changes. Exact engine pin is unchanged.

`nostr-tools` 2.25.2 was the registry's stable release at implementation (patch after phase-0's 2.25.1). Exact direct pin and frozen transitive lock. Pure JS cryptography; no NAPI introduced. The package's published `source` exports reference absent files; a small loader locates the pinned package and loads its published CJS artifacts, preserving the harness's source test condition.

Scope is one-to-one text kind-14 rumors in kind-13 signed seals / kind-1059 signed wraps, NIP-44 v2. No custom Buzz kinds, group DMs, files or NIP-04. Signed recipient kind-10050 metadata is required; only configured and Egress-permitted advertised relays receive that copy. Own archive wraps go to own configured relays. Relay acceptance requires OK; this does not prove end-user receipt.

## Threat table

| Attack | Protection | Evidence |
| --- | --- | --- |
| Forged or substituted event | outer + seal signature, author binding, rumor hash | buzz.test invalid signatures; real crypto roundtrip |
| Unknown sender / group expansion | normalized allowlist, exactly one recipient | buzz.test unknown sender and contract/group exclusion |
| Relay SSRF / credentials | fixed configured URLs, pinned Egress, anonymous handshake | socket.test real loopback; denied egress test |
| Replay, including different wrap of same rumor | durable outer and rumor claims before dispatch | buzz.test re-wrap and private file persistence |
| Memory pressure | transport 1 MiB, adapter 128 KiB event, 16 KiB text, queue 128 | size test and explicit bounded queue |
| Secret disclosure | SecretStore-only key, fixed log/error vocabulary | redaction and missing-secret tests |
| DM turn blocks relay control | nonblocking bounded turn queue, metadata/control separate | socket.test sends late metadata and ACK during receive→send |

## Behaviour changes

Disabled by default. Independent relay loops with capped exponential backoff/jitter, reset only after a stable connection. Stop aborts connects/backoff/ACK waits, closes sockets and erases key bytes. Shared behaviour policy applies to ingress, /link and egress. Pairing still needs the person's explicit confirmation; code parameters are unchanged.

## Owner questions

None for approved scope. Existing pairing-code entropy question remains unchanged. Encrypted transport is not an anonymity claim.

## Hotspots

Additive core bindings/switchboard dependency injection; optional auth in voice/socket; config schema and generated files; engine provider declarations. No modifications to engine repository or other adapters.

## Validation

Node 24.21.0. Buzz real-crypto/fake-relay and real pinned loopback socket tests; four-channel host-fake persona test uses the actual composition prompt and provider router for the same agent, with real pairing on each channel. Existing full channel/host subset: 253 tests, 252 passed, one existing explicit TODO. `pnpm lint`, generation/docs and frozen installation passed before final focused additions; final results are recorded in the execution ledger. No live public relay, five-platform execution or CI polling.

## Known gaps

No indefinite dedupe guarantee: 65,536 retained IDs plus a 48-hour event-age gate; interrupted claimed turns can be lost (at-most-once). Recipient DM metadata is fetched again on reconnect/restart, with a bounded wait; no allowed advertised relay means refusal. NIP-42 challenge signing is implemented, but relays requiring a fresh subscription after authentication may need manual reconnect; no full authenticated-relay interoperability claim. Persona acceptance covers channel host fakes; real adapter contracts are tested separately.

Follow-up verification: Core keeps Buzz/Matrix as external workspace package boundaries so deployed crypto resolution works. Buzz start is idempotent; recipient ACK is mandatory, own archive is best effort; Unicode limits count UTF-8 bytes. The new private-key reference follows the log-schema credential-reference convention (eight references, no new config-held secret value). Focused Buzz tests pass, including these regressions.
