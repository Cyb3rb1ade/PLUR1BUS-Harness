Owner request (2026-10-07): the Agent Bridge must cover DeepSeek Harness (GUI + CLI), Qwen (desktop + CLI), Grok (bot, CLI), Cursor CLI, GitHub Copilot (CLI + desktop), claw-code, Pi, OpenCode, Cline, Aider, Kilo Code, Amazon Q / Bedrock and nanobot, in addition to the systems already named (Claude Code, Codex CLI, Kimi, `agy`, Claude Desktop, Jan, LibreChat, Open WebUI, OpenClaw, Hermes, NanoClaw, ZeroClaw).

Checked 2026-10-07. Method: npm/PyPI registry metadata plus the shipped package contents (READMEs, bundled docs and source strings in the tarballs), vendor docs via web fetch, and web search. GitHub API access was blocked in this session, so GitHub stars, releases and licence files were not read directly.

Legend
- **Drive** (ADR-011): T1 = ACP (Agent Client Protocol), T2 = headless JSON/stream mode, T3 = PTY.
- **Attach** (host-adapters.md): 0 = custom OpenAI/Anthropic base URL (memory proxy), 1 = pluggable memory-provider slot or plugin, 2 = pre/post-turn hooks that can inject context, 3 = MCP client plus an instructions file.
- **Evidence**: **V** = verified 2026-10-07 from the primary source (vendor docs or shipped package). **P** = partly verified; the unverified items are marked "(unverified)" in the cell. **U** = unverified.
- Login storage gives the path only, for detection. No secrets were read.

## Notes and ambiguities

1. **"DeepSeek harness GUI + CLI" exists and is official.** DeepSeek Harness (`dsh`) is published under the `@deepseek-ai` npm scope by DeepSeek maintainers (`tianyicui-deepseek`, `imccyu`), with repo `deepseek-ai/deepseek-harness`, licence MIT, and status developer preview. The web GUI is `dsh web` (`127.0.0.1:3080`). The macOS/Windows desktop app (v0.2.0, 2026-09-29) comes from a third-party article and can install the `dsh` CLI; the CLI reserves the profile name `desktop` for the Electron host, which corroborates it. Community wrappers (`HaoyueQin/deepseek-harness-desktop`, `liguobao/dsh-desktop`, snap `dsh-desktop-community`) are **not** official. The ACP profile is "automation-only": it streams only committed assistant text and does not expose tool calls or plans. Its MCP-in-session/new behaviour differs between two README versions, so test it.
2. **Grok has two candidates:** the official `@xai-official/grok` (xAI, `x.ai/cli`; native ACP via `grok agent stdio`) and the community `superagent-ai/grok-cli` (`@vibe-kit/grok-cli`). Target the official one. "grok bot" most plausibly means Grok in Telegram (official xAI–Telegram partnership) or @grok on X. Neither surface is drivable or attachable, so only the xAI API works, as a provider profile. If the owner meant a self-hosted Telegram bot that uses Grok, that is just a provider.
3. **Cursor:** the binary is now `agent`, while docs and older installs still use `cursor-agent`. Detect both.
4. **Copilot:** the CLI is closed source, but its licence explicitly allows embedding unmodified copies in an app with material extra functionality. ACP is public preview. The Copilot desktop app and VS Code agent mode are GUI-only, so drive the CLI.
5. **Pi moved** from `@mariozechner/pi-coding-agent` / `badlogic/pi-mono` to `@earendil-works/pi-coding-agent` / `earendil-works/pi` (v1.0.x). Its `--mode rpc` is a richer drive path than T2. Pi has no MCP by design, so attach-3 needs an extension; persona and memory are best done as a Pi extension (`before_agent_start` / `context`).
6. **Qwen Code has a real memory-provider slot** (`memory.mem0`, three pinned REST contracts). This is the cleanest attach-1 among the new systems: the harness would implement a mem0-OSS-compatible `/search` and `/memories` endpoint.
7. **Kimi:** the "kimi-cli" listed in our docs is archived. Kimi Code CLI (new repo, new data root `~/.kimi-code/`) replaces it, and the detection paths must change.
8. **Amazon Q Developer CLI was replaced by Kiro CLI** and its licence went from Apache-2.0 to the closed AWS IP License. Config moved from `~/.aws/amazonq/` to `~/.kiro/`. Bedrock is a provider, not an engine; Bedrock Agents and AgentCore would need a remote-API engine adapter, not T1–T3.
9. **ACP adapters were renamed** to the `@agentclientprotocol/*` scope: `claude-agent-acp` 0.86.0 and `codex-acp` 2.1.1. The `@zed-industries/*` packages are stale.
10. **claw-code:** "Claw code" maps to `ultraworkers/claw-code` (MIT, Rust, clean-room). It has no ACP yet, its JSON output is non-streaming, it is build-from-source only, and it describes itself as an agent-managed exhibit, so its stability is doubtful. Its MCP and hooks support could not be verified.
11. **Aider** has had no release since 2026-02-12, has no MCP, no ACP and no JSON output. It is only usable via text T2 or T3 plus attach-0.
12. **ToS summary:** Anthropic Free/Pro/Max OAuth is for Claude Code and Claude.ai only; any third-party harness routing should use API keys. A Google forum reply tolerates spawning `agy` under the user's own login. The Copilot licence restricts redistribution form only. Cursor and Kiro have no explicit harness clause found.
13. **Not verified because the GitHub API was blocked:** repository licence files for Aider, OpenCode and Codex; current versions for Cursor, Kiro, `agy` and Claude Desktop; the rows for NanoClaw, Jan, LibreChat and OpenWebUI.
