# Doctor report

`doctor.report` serves the Core's cached projection of the authoritative `plur1bus --json 1staid check` report. Core performs an internal startup check; reads use that snapshot. `refresh: true` runs another check for Owner, Admin or Operator, at most once per 30 seconds. All human roles may read under the `agent.list` admission scope; refresh additionally needs `doctor.run`, so read-only scoped tokens cannot force checks. Concurrent refreshes and requests inside that interval return `E_CONFLICT` with `reason: refresh-rate-limit`. Missing CLI/check output returns `E_NOT_AVAILABLE`.

The `provisioning` group includes check IDs, normalized statuses, redacted summaries and repair hints. Raw detail, stderr and full home paths are omitted. Checks absent from the existing Rust source (containers, secret presence, certificates, ports and disks in this revision) are explicitly `skipped`; they are not claimed as verified. Completing these authoritative checks remains open.

The Doctor page reads this report alongside its existing health and uploaded-report views. The health refresh button is natively disabled while the current request is pending, fixing the previous race where a click could be silently dropped before loading finished.

RE-D172 appends three rows for the native Rust engine, `engine.process`, `engine.store` and `engine.runtime` (positions 37 to 39, after `dreams.learn.backlog`). All three `skip` while the Node engine is selected (`engine.implementation: "node"`, the default). With `"rust"` one bounded `engine.status` call inside the check budget serves every row: `engine.process` is `ok` when `run/engine.pid` names the process that serves the engine endpoint and it reports `process.state: ready` (`warn` when orphaned or stopping, `fail` when the pid file names another process); `engine.store` reads `storeSchema`, `jobs.ledger` and `journal` (`fail` on a schema mismatch, `warn` without a store, with an unavailable ledger or a journal backlog); `engine.runtime` reads the `models` block (`fail` when the embedder failed, `warn` while models load or when the reranker failed). An engine that does not answer fails `engine.process` once with a hint to `plur1bus daemon status`; the other two rows then read "not checkable" (`skip`) and no second connection is made. On Windows `windows.pipe-acl` checks the engine pipe as well and lists the pipes it read in `detail.checked`.

D120 adds the append-only `tools.service` row: `ok` when Core’s cached `tools.health` probe reports ready, `fail` when tools is down, and `skip` when Core is unavailable. The live doctor overlay uses the same Core probe without starting a second process. Core continues serving turns during tools restarts.

The Core-owned `external.agents.sandbox` row reports ACP process policy separately from `tools.sandbox` and `tools.sandbox.tasks`. On macOS it fails with `sandbox-unavailable (macos-acceptance-pending)` for agents, terminals and discovery probes while ordinary Seatbelt tools retain their own availability. Windows also refuses ACP without the Mac acceptance cause; Linux requires available bubblewrap, the `namespace-limit` task mechanism and a positive safe-integer `tools.sandbox.maxTasks` (zero refuses ACP), with connector acceptance checked separately. Native macOS acceptance remains D123 SB-1/SB-3; the fixed cause also appears in the bounded `external.agent.refused` Core event.
