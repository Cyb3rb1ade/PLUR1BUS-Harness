# Log schema reference (log-schema 1.0.0)

Generated by `scripts/gen-docs.mjs` from `packages/log-schema/schema/{record.schema,audit.schema,catalogue,levels,redaction}.json` —
do not edit by hand; run `pnpm docs:gen`. Design: `docs/superpowers/specs/2026-10-01-logging-and-diagnostics-design.md` (D111).
The TypeScript package `@plur1bus/log-schema` and the Rust crate `plur1bus-log-schema` both read these files;
`packages/log-schema/fixtures/vectors.json` and `crates/plur1bus-log-schema/tests/parity.rs` keep them in agreement.
This package holds the schema, catalogue, level map and redaction patterns as data and one validator. It contains no
logger, writer, redactor or sink.

## Record

One JSON object per line, UTF-8. Keys are written in this order (grep-stable); absent optional keys are omitted:
`ts`, `level`, `source`, `event`, `msg`, `trace_id`, `span_id`, `agent`, `session`, `turn`, `task`, `principal`, `duration_ms`, `err`, `stream`, `attrs`.

| Field | Type | Rule |
|---|---|---|
| `ts` | `string` | RFC 3339 UTC, millisecond precision, the writer's clock (OTel Timestamp). **Required.** |
| `level` | `trace` \| `debug` \| `info` \| `warn` \| `error` \| `fatal` |  **Required.** |
| `source` | `Source` |  **Required.** |
| `event` | `string` | Stable dotted code from the registered catalogue (OTel event.name). **Required.** |
| `msg` | `string` | Harness-authored, constant per event; no interpolated foreign text (OTel Body). At most 2 KiB (bytes; checked by the validator). **Required.** |
| `trace_id` | `string` | W3C trace id. |
| `span_id` | `string` | W3C span id. |
| `agent` | `HarnessId` |  |
| `session` | `HarnessId` |  |
| `turn` | `integer` |  |
| `task` | `HarnessId` |  |
| `principal` | `HarnessId` | The ADR-007 pseudonymous principal; never a name, email or channel handle. |
| `duration_ms` | `integer` |  |
| `err` | `Err` |  |
| `stream` | `stdout` \| `stderr` | Only on wrapped child output (OTel log.iostream). |
| `attrs` | `object` | Event-specific; narrowed by the catalogue entry's attrs group. At most 8 KiB after redaction (bytes; checked by the validator). |

`source` is `{ kind, id, version }`, all three required (`version` may be `null`). `source.kind`: `harness`, `extension`, `provider`, `model`, `cli`, `channel`, `host`, `desktop`, `os`.
A source key (for `logs.levels` and filters) is `<kind>` or `<kind>:<id>`, matching `^(harness|extension|provider|model|cli|channel|host|desktop|os)(:[a-z0-9][a-z0-9._@/-]{0,127})?$`.
`err` is `{ code, reason?, retryable?, hint? }` with `code` one of `E_AGENT_UNKNOWN`, `E_APPROVAL_REQUIRED`, `E_CONFIG_INVALID`, `E_CONFLICT`, `E_CORE_UNAVAILABLE`, `E_DENIED`, `E_INTERNAL`, `E_INVALID_PARAMS`, `E_LOCKED`, `E_MODULE_UNKNOWN`, `E_NOT_AVAILABLE`, `E_NOT_FOUND`, `E_RPC_VERSION`, `E_STORAGE`, `E_UNAUTHORIZED`, `rate-limited`, `overloaded`, `auth`, `invalid-request`, `server`, `timeout`, `network`.

Limits: `msg` ≤ 2048 bytes, `attrs` ≤ 8192 bytes (compact JSON), a wrapped output line ≤ 4096 bytes, dedup window 60000 ms,
child output rate 100 lines/s sustained with a burst of 500.

### Validation

JSON Schema cannot express key order, byte limits or the catalogue, so `validateRecord`/`validateLine` (TypeScript) and
`validate_line` (Rust) check those on top of the schema, in this order; the first failure names the code:

1. `not_object` — not a JSON object (a repeated top-level key is `key_order`)
2. `invalid_level` — `level` is not one of the six
3. `unknown_event` — `event` is not in the catalogue; `wrong_stream` — it is an audit action (use the audit record)
4. `msg_too_long` — `msg` over its byte limit
5. `attrs_too_large` — `attrs` over its byte limit
6. `schema` — the record schema, plus a real calendar date and time in `ts`
7. `key_order` — keys out of the order above
8. `level_not_allowed` — the level is not one the event allows
9. `source_kind_not_allowed` — the event may not be emitted by this source kind
10. `stream_mismatch` — `stream` present iff the event is wrapped child output
11. `attrs_invalid` — `attrs` do not match the event's attrs group (closed, with the event's required attrs)

## Audit record

Audit is its own record type (spec R1): the v1 fields of `logs/audit.log` are kept unchanged and D111 only adds optional fields to new lines. It has no `ts`, `level` or `msg`.
Keys are written in this order: `at`, `actor`, `action`, `target`, `detail`, `v`, `source`, `trace_id`, `agent`, `session`, `task`, `surface`, `store_ref`. A reader aliases `at` to `ts`, `action` to `event` and `actor` to `principal`.

| Field | Type | Rule |
|---|---|---|
| `at` | `integer` | Epoch milliseconds (a number, not a string). **Required.** |
| `actor` | `object` (`user`, `host`) |  **Required.** |
| `action` | `string` | A registered audit event name. **Required.** |
| `target` | `string` |  **Required.** |
| `detail` | `object` | Narrowed by the catalogue entry's attrs group; at most 8 KiB (bytes; checked by the validator). **Required.** |
| `v` | `2` | Present on lines written under D111; absent on v1 lines. |
| `source` | `Source` |  |
| `trace_id` | `string` |  |
| `agent` | `HarnessId` |  |
| `session` | `HarnessId` |  |
| `task` | `HarnessId` |  |
| `surface` | `string` | Where the action came from (cli, desktop, api, …). |
| `store_ref` | `string` | D109 mirror lines: row id and chain value of the authoritative store row (R2). |

`validateAuditRecord`/`validateAuditLine` (TypeScript) and `validate_audit_line` (Rust) check: object → `action` is an audit-stream catalogue entry → `detail` bytes → schema → key order → source kind (when `source` is present) → `detail` against the entry's attribute group. An audit action written as a diagnostic record is refused with `wrong_stream`.

## Levels

| Level | Rank | OTel SeverityNumber | OTel SeverityText | syslog (RFC 5424) | Meaning |
|---|---|---|---|---|---|
| `trace` | 0 | 1 | TRACE | 7 (debug) | step-by-step internals; only for a limited time (logs.traceUntil) |
| `debug` | 1 | 5 | DEBUG | 7 (debug) | developer detail, successful routine operations |
| `info` | 2 | 9 | INFO | 6 (informational) | state changes a person may want to see; every skip with its reason (ADR-009) |
| `warn` | 3 | 13 | WARN | 4 (warning) | degraded but self-healing, retrying, or a limit reached |
| `error` | 4 | 17 | ERROR | 3 (error) | an operation failed and will not succeed without a retry decision or intervention, proven by a hard signal |
| `fatal` | 5 | 21 | FATAL | 2 (critical) | a process or service died |

## Event catalogue

Events are stable API (R10): a rename is a new event plus a deprecation. A name matches `^[a-z][a-z0-9_-]*(\.[a-z0-9][a-z0-9_-]*){1,3}$`; `repair.*`
is a family (any `repair.<step>`). In the Level column the default level is **bold**. "Experimental" marks events whose
emitters land in later parts of D111; the names are already reserved.

### Attribute groups

Every event's `attrs` are closed: the common attributes below plus the event's group, and nothing else.

| Attribute | Type | Meaning |
|---|---|---|
| `repeat` | `integer` | dedup summary: all occurrences in the window, the first included (§2.9) |
| `window_ms` | `integer` | dedup or rate-limit window length |
| `link_trace_id` | `string` | a foreign trace id that was not adopted (§2.8) |
| `foreign_message` | `string` | untrusted foreign error text, truncated and redacted by the writer |
| `untrusted` | `boolean` | true on wrapped third-party output |
| `truncated` | `boolean` | the value was cut to its limit |

## Redaction data

The writer applies these rules in order (`secret`, `key`, `pattern`, `url`, `path`, `pii`) to `msg`, `attrs`, `err`, wrapped text and audit detail; a match is
replaced by `[REDACTED:{rule}]`. Patterns use the subset common to ECMAScript and the Rust `regex` crate.

- **`secret`** (registry, §4 rule 1): Exact secret-store values and leases the process holds (ADR-005), plus their base64 and URL-encoded forms; the registry is in memory only.
  - minimum length 8, encodings: raw, base64, url
- **`key`** (key-name, §4 rule 2): A JSON key, key=value pair or header whose name matches has its value replaced. A name matches when one of its delimited segments is a listed word, or (camelCase names) when it contains the word as a capitalised part. Plural token counts (input_tokens, outputTokens, max_tokens) are not credentials and do not match; `token` alone, access_token, accessToken and id_token_hint do.
  - names (flags `i`): `(?:^|[^a-z0-9])(?:authorization|proxy-authorization|cookie|set-cookie|token|secret|password|passwd|api[_-]?key|client[_-]?secret|refresh|code_verifier|ticket|csrf|id_token_hint|private[_-]?key|session[_-]?key)(?:[^a-z0-9]|$)`
  - camelCase names (case-sensitive): `[a-z](?:Token|Secret|Password|Passwd|ApiKey|Cookie|Authorization|Ticket|Csrf|PrivateKey|SessionKey|Refresh|ClientSecret)(?:[A-Z]|$)`
- **`pattern`** (patterns, §4 rule 3): Credential shapes redacted wherever they occur.
  - `bearer`: `Bearer\s+\S+` (flags `i`) — Bearer token
  - `basic`: `Basic\s+[A-Za-z0-9+/]{8,}={0,2}` — Basic credentials (case-sensitive and at least 8 characters, so prose such as "Basic info" survives)
  - `sk`: `sk-(?:ant-|proj-)?[A-Za-z0-9_-]{20,}`, left boundary — sk-…, sk-ant-…, sk-proj-… API keys
  - `ek`: `ek_[A-Za-z0-9_-]{16,}`, left boundary — ek_… values (D110)
  - `ghp`: `ghp_[A-Za-z0-9]{36,}`, left boundary — GitHub personal access token
  - `github-pat`: `github_pat_[A-Za-z0-9_]{22,}`, left boundary — GitHub fine-grained token
  - `slack`: `xox[abpr]-[A-Za-z0-9-]{10,}`, left boundary — Slack token
  - `aws-access-key`: `AKIA[0-9A-Z]{16}`, left boundary — AWS access key id
  - `google-api-key`: `AIza[0-9A-Za-z_-]{35}`, left boundary — Google API key
  - `jwt`: `eyJ[A-Za-z0-9_-]+\.eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+` — JSON Web Token
  - `pem-private-key`: `-----BEGIN [A-Z0-9 ]*PRIVATE KEY-----[\s\S]*?(?:-----END [A-Z0-9 ]*PRIVATE KEY-----|$)` — PEM private-key block; an unterminated block is redacted to the end of the text
  - `plur1bus-env`: `PLUR1BUS_[A-Z0-9_]+=(\S+)`, replaces group 1 — the value of a PLUR1BUS_* environment assignment; the name stays
  - `base64url-run`: `[A-Za-z0-9_-]{43,}`, exempt when the whole match is `^[0-9A-Fa-f]+$` — base64url runs of 43 or more characters, unless the run is pure hex (SHA-256, git ids and the extension audit's sha256 stay readable)
- **`url`** (url, §4 rule 4): Inside any URL: userinfo removed, query values and the fragment replaced, parameter names kept.
  - finds URLs with `[A-Za-z][A-Za-z0-9+.-]*://[^\s"'<>]+`, then applies, in order:
  - `userinfo`: `(://)([^/\s?#@]+@)`, replaces group 2 — user:pass@ removed
  - `query-value`: `([?&][^=&#\s]*=)([^&#\s]*)`, replaces group 2 — query values replaced
  - `fragment`: `(#)(.+)$`, replaces group 2 — fragment replaced
- **`path`** (deny-paths, §4 rule 5): A path that canonicalises under a credential deny-list entry is replaced by the entry class and a short hash of the canonical path: <deny:ssh>/…#3f9a1c.
  - `ssh`: `.ssh`
  - `gnupg`: `.gnupg`
  - `keychain`: `Library/Keychains`
  - `browser-profile`: `.mozilla`, `.config/google-chrome`, `.config/chromium`, `Library/Application Support/Google/Chrome`, `Library/Application Support/Firefox`, `AppData/Local/Google/Chrome`, `AppData/Roaming/Mozilla`
  - `password-manager`: `.config/1Password`, `Library/Group Containers/2BUA8C4S2C.com.1password`, `.config/Bitwarden`, `AppData/Roaming/Bitwarden`, `.password-store`
  - `cloud-cli`: `.aws`, `.azure`, `.config/gcloud`, `.kube`, `.docker/config.json`, `.config/gh`
  - `dotenv`: `.env`, `.env.*`, `.npmrc`, `.netrc`, `.pgpass`
- **`pii`** (patterns, §4 rule 6): Email addresses and phone numbers; applied only when logs.redactPii is true (default false). Enabled by `logs.redactPii` (default false).
  - `email`: `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}` — email address
  - `phone-e164`: `\+[1-9][0-9]{6,14}` — E.164 phone number
  - `phone-nanp`: `\(?[0-9]{3}\)?[ .-][0-9]{3}[ .-][0-9]{4}` — North American number with separators
  - `phone-national`: `0[0-9]{2,4}[ /-][0-9]{4,8}` — national format with a leading 0 and a separator (e.g. 030 12345678)

Never logged at all (not redacted — not written): response bodies and fetched content (D94); file contents (D109 §9); tool results (D109 §9); transcripts and conversation content; desktop panel page content and URLs (desktop spec §6.9); LLM prompt and response payloads outside an active, time-limited payload capture (§2.5).
