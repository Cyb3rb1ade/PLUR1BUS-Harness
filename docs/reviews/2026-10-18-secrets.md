## 1. Übersicht und Abnahmekriterien

In PR #568 und PR #574 wurden zentrale Owner-Entscheidungen vom 17./18.10.2026 zu Secrets umgesetzt:
1. Automatische Maskierung (`[REDACTED:secret]`) in allen Protokoll- und Diagnosesenken.
2. Das Tool `secret_names` für Agenten liefert nur deklarierte Namen und Präsenz, niemals Werte oder Längen.
3. Jedes Secret erhält eine optionale Beschreibung (`description`, <= 200 Zeichen, einzeilig), die niemals den geheimen Wert enthalten darf.
4. Ausgehende POST-Requests für A2A-Push und OAuth-Tokens laufen zwingend über den Egress-Dienst (`egress.request`).

### Abnahmekriterien & Prüfpunkte:
1. **Redaction in allen Senken:**
   - `core.log`: Registrierung über `secretStore.redaction.subscribe(...)`. (Erfüllt)
   - Audit-Log: `createPolicyAudit` verwendet `secretStore.redaction.redactor()`. (Erfüllt)
   - `logs.query` und `logs.tail`: Dynamische Redaction auf Lesepfad mit `redactor`. (Erfüllt)
   - Doctor-Report: `buildDoctorMethods` nutzt `redactor({ pii: true })`. (Erfüllt)
2. **`secret_names`-Tool:**
   - Keine Argumente (`inputSchema: { type: "object", additionalProperties: false }`).
   - Identität fest an `ctx.agentId` gebunden; liest nur Agent-spezifische Config-Slots.
   - Kein Leak von Länge, Präfix oder Existenz fremder Secrets; kein Timing-Leak. (Erfüllt)
3. **Secret-Beschreibung:**
   - Validierung in `checkDescription`: maximal 200 Zeichen, keine Steuerzeichen / Zeilenumbrüche.
   - Verhindert das Einfügen des Werts (`text.includes(value)`). (Erfüllt, mit Einschränkung bei Kurzwerten, siehe m2)
4. **POST-Egress für A2A-Push und OAuth:**
   - `a2a/push.ts` und `auth/http.ts` öffnen keine eigenen Sockets mehr; Routing über `egress.request`.
   - Statischer Guard-Test (`test/egress/post-paths.test.ts`) verhindert direkte Socket-Imports. (Erfüllt)

## 3. Befunde

### Blocker
Keine.

### Major
Keine.

### Minor / Nit

#### m1 (Minor) — Älteste Secrets werden bei mehr als 256 Einträgen aus dem Redactor verdrängt (`packages/core/src/secrets/redaction.ts:7, 24`)
- **Datei:Zeile:** `packages/core/src/secrets/redaction.ts:7`, `redaction.ts:24`
- **Begründung:**
  In `createSecretRedaction` ist die Menge der registrierten Secret-Werte auf 256 beschränkt:
  ```ts
  export const MAX_REGISTERED_SECRETS = 256;
  ...
  if (values.size > MAX_REGISTERED_SECRETS) values.delete(values.values().next().value!);
  ```
  Werden in einer langlebigen Instanz durch häufige Schlüssel-Rotationen, dynamische Leases oder viele Accounts mehr als 256 Secrets registriert, wird der älteste Wert per FIFO aus dem Speicher-Set gelöscht.
  Treten historische Protokollzeilen mit diesem alten Secret auf und werden später über `logs.query` oder den Doctor abgefragt, wird der Wert nicht mehr maskiert.
  Zwar existiert im Log-Writer selbst kein `unregisterSecret`, aber der dynamische Redactor für `logs.query` und Doctor verliert die Schutzwirkung für verdrängte Werte.
- **Auflage / Empfehlung:** Entweder Obergrenze erhöhen oder bei Verdrängung einen Hash-basierten Fallback (z. B. Bloom-Filter oder persistiertes Aho-Corasick-Wörterbuch) vorsehen.

#### m2 (Minor) — `checkDescription` erkennt Geheimwerte unter 8 Zeichen nicht (`packages/core/src/secrets/types.ts:75`)
- **Datei:Zeile:** `packages/core/src/secrets/types.ts:75`
- **Begründung:**
  In `checkDescription` lautet die Prüfung:
  ```ts
  if (value !== undefined && value.length >= 8 && text.includes(value)) throw new SecretError("invalid-description", "secret description must not contain the secret value");
  ```
  Hat ein Secret weniger als 8 Zeichen (z. B. ein kurzer Test-Pin oder Legacy-Kennwort "geheim1"), schlägt die Prüfung fehl und die Beschreibung darf den Klartextwert enthalten.
  Zudem wird nur gegen das aktuell geschriebene Secret geprüft, nicht gegen andere im Store vorhandene Werte.
- **Auflage / Empfehlung:** Als Richtlinie im Handbuch klarstellen, dass Secrets mindestens 8 Zeichen lang sein müssen (was ohnehin Best Practice ist).

#### m3 (Nit) — Aktualisierung nur der Beschreibung erfordert erneute Eingabe des geheimen Werts (`packages/core/src/secrets/store.ts:60`)
- **Datei:Zeile:** `packages/core/src/secrets/store.ts:60`
- **Begründung:** Da `secret.set` immer zwingend den Parameter `value` verlangt, kann die Beschreibung eines Secrets nicht isoliert geändert werden, ohne das Secret erneut zu übermitteln. (Gewolltes Design zur Vermeidung von Schema-Bloat).
