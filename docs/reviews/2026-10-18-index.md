## 2. Kernbefunde & Handlungsbedarf vor Rollout

### Blocker für den stabilen Betrieb (Majors)

1. **RPC-Verbindungstrennung bei Event-Burst (Thema 1, M1):**
   - **Ort:** `packages/module-api/src/rpc-server.ts:306-309`
   - **Problem:** Jedes eingehende Event erhöht den Zähler `pendingNotifications` für **jede** aktive Verbindung, bevor geprüft wird, ob die Verbindung für das Event autorisiert ist oder das Agent-Targeting zutrifft. Sendet ein Agent 1024 Events in kurzer Folge, überschreitet die Queue unbeteiligter Verbindungen das Limit `MAX_PENDING = 1024` und der Server trennt deren Socket mit `c.sock.destroy()`.
   - **Abhilfe:** `pendingNotifications` erst nach der Filterung (`sub.agentId`, `opts.audience`, RBAC) inkrementieren.

2. **Genehmigungs-Zustellung komplett blockiert (Thema 1, M2):**
   - **Ort:** `packages/core/src/approvals/notify.ts:48-69`
   - **Problem:** Die Funktion prüft alle registrierten Abonnenten in einer Schleife. Besitzt auch nur eine einzige verbundene Entität (z. B. ein Hintergrund-Agent) kein `approval:read`, wird die Benachrichtigung für **alle** Verbindungen abgebrochen. Dies führt zu einem Totalausfall von Approval-Benachrichtigungen für menschliche Operatoren im Web-UI.
   - **Abhilfe:** Autorisierungsprüfung pro Empfänger durchführen und Events gezielt nur an berechtigte Verbindungen zustellen (`deliverToConnection`).

3. **Plattform-Defizit bei Sandbox D106 (Thema 2, M1):**
   - **Ort:** `packages/core/src/sandbox/windows.ts` und `packages/core/src/sandbox/bubblewrap.ts`
   - **Problem:** Unter Windows meldet `detectSandbox()` dauerhaft `available: false`. Unter Linux bricht Bubblewrap ab, sobald ein Arbeitsverzeichnis beschreibbare Wurzeln erfordert (`writeRoots.length > 0`). Lediglich unter macOS funktioniert die Sandbox mit Schreibrechten.
   - **Abhilfe:** Entweder die Nicht-macOS-Plattformen in den Release-Notes explizit als experimentell/ungestützt deklarieren oder die Implementierung der Windows-Token-Restriktionen und Linux-OverlayFS-Bind-Mounts fertigstellen.

## 3. Methodik & Transparenzhinweis

- **Basis:** `origin/main` auf Commit `2b5a435c071a723e480e9032bbf03b956fa2191d`.
- **Branches:** Noch nicht gemergte Features wurden direkt auf ihren Feature-Branches analysiert und verifiziert.
- **Transparenz:**
  - Getestet wurde auf macOS (Darwin ARM64).
  - Windows- und reine Linux-Kernel-Mechanismen (z. B. Bubblewrap-Namespaces, NTFS Junctions, 8.3-Shortnames) wurden anhand von statischer Code-Analyse, Typ-Definitionen und Test-Suites bewertet.
  - Externe Cloud-Modell-APIs (OpenAI, OpenRouter, Cohere) wurden mit Mock-/Fake-Providern geprüft; es wurden keine echten API-Schlüssel oder Live-Aufrufe getätigt.
