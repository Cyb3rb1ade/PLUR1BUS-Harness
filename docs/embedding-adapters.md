# Embedding and rerank adapters

Hand-written. Code: `packages/embedding-adapters/`. Decision record: `docs/adr/ADR-006-embedding-and-reranking.md`.

`@plur1bus/embedding-adapters` is one interface over every remote embedding and rerank provider named in ADR-006, with
shared timeout, retry, batching, response validation and secret handling. It adds **no runtime dependencies** (Node
`fetch`, `AbortController`, web streams only). **It is not wired into core or the engine** (see
[Follow-up: wiring](#follow-up-wiring-into-coreengine)).

## Interface

```ts
interface EmbeddingAdapter {
  id: string;                                   // "<provider>:<model>"
  identity(): EmbeddingIdentity;                // deterministic, frozen
  embed(texts, { inputType: "query" | "document", signal? }): Promise<Float32Array[]>;
}
interface RerankAdapter {
  id: string;
  rerank(query, docs, { topN?, signal? }): Promise<{ index: number; score: number }[]>;  // best first
}
```

`embed` returns one vector per input in input order, however the work was batched or the server ordered its answer.
Adapters throw `AdapterError` only.

Secrets: adapters never read `process.env`. The caller injects `getSecret(name)`; the config only holds the *name*.

```ts
import { createEmbeddingAdapter, createRerankAdapter, egressHosts } from "@plur1bus/embedding-adapters";

const embed = createEmbeddingAdapter(
  { provider: "openai", model: "text-embedding-3-small", dimensions: 1536, secretName: "openai.key" },
  { getSecret: (name) => vault.get(name) },
);
const vectors = await embed.embed(["some text"], { inputType: "document" });
```

## Providers

Status is about the **wire format**. "Documented" means built from the provider's public API documentation and
ADR-006; **no row has been run against a live service in this PR** (no keys, no network in CI). The optional live
smoke (below) is how a row becomes "live-verified".

### Embedding

| Provider id | Endpoint (default base URL) | Input type | Max batch / tokens (defaults) | Notes | Wire status |
| --- | --- | --- | --- | --- | --- |
| `openai` | `POST /embeddings` (`https://api.openai.com/v1`) | none (symmetric) | 256 / 8192 | `dimensions` sent (matryoshka) | documented |
| `openai-compatible`, `vllm`, `llamacpp`, `omlx` | `POST {baseURL}/embeddings` | none | 64 / 512 | `baseURL` required, no `dimensions`, secret optional | documented (OpenAI shape) |
| `openrouter` | `POST /embeddings` (`https://openrouter.ai/api/v1`) | none | 128 / 8192 | `pinnedUpstream` **required**; sent as `provider: {order:[upstream], allow_fallbacks:false}`; identity revision `upstream:<name>` | documented |
| `google` | `POST /models/{model}:batchEmbedContents` (`:embedContent` for one text) | `taskType` RETRIEVAL_QUERY / RETRIEVAL_DOCUMENT | 100 / 2048 | key in `x-goog-api-key` header, never the URL; `outputDimensionality` | documented; ADR notes `task_type` only applies to `-001` models, `gemini-embedding-2` is untested |
| `cohere` | `POST /v2/embed` | `input_type` search_query / search_document | 96 / 512 | `embedding_types:["float"]` | **unverified** (ADR-006: primary doc 404'd) |
| `jina` | `POST /embeddings` (`https://api.jina.ai/v1`) | `task` retrieval.query / retrieval.passage | 128 / 8192 | OpenAI-shaped response | **unverified** |
| `voyage` | `POST /embeddings` (`https://api.voyageai.com/v1`) | `input_type` query / document | 128 / 32000 (+100k per batch) | `output_dimension`, `truncation:false` | **unverified** |
| `ollama` | `POST /api/embed` (`http://127.0.0.1:11434`) | none | 64 / 512 | `truncate:false` | documented |
| `tei` | `POST /embed` | none (use prefixes) | 32 / 512 | root-array response, `truncate:false` | documented |
| `mtplx` | `POST {baseURL}/v1/embeddings` (daemon, default `http://127.0.0.1:8000`) | none (an `instruction` field exists server-side, unused) | 32 / 8192 | OpenAI shape; `dimensions` sent, the server truncates (Matryoshka) and answers 400 above the native width; embedding models are opt-in on the daemon (`--embedding-model`), otherwise 404 | source-verified (`mtplx/server/openai.py`), not live |

Limits are conservative defaults, not provider maxima; every one is overridable (`maxBatch`, `maxInputTokens`, `maxBatchTokens`).
Token counts are an estimate (`ceil(ascii/4 + other/1.5)`); an input over `maxInputTokens` fails with `too_large` before any request.
Models that need a client-side prefix (e5 style) use `queryPrefix` / `passagePrefix`; both are part of the identity.

### Rerank

Frozen request/response mapping (`RERANK_SHAPES`, generated by `renderRerankMappingTable()`). A response that does not
match its row is `bad_response` naming the keys it did contain; the adapter never guesses an alternative layout.

| Provider | Request | Response | Status | Live result |
| --- | --- | --- | --- | --- |
| cohere | `{model, query, documents[], top_n}` | `{results:[{index, relevance_score}]}` | verified | not run |
| voyage | `{model, query, documents[], top_k}` | `{results:[{index, relevance_score}]}` | verified | not run |
| jina | `{model, query, documents[], top_n}` | `{results:[{index, relevance_score}]}` | unverified | not run |
| tei | `{query, texts[]}` | `[{index, score}]` | unverified | not run |
| vllm | `{model, query, documents[], top_n}` | `{results:[{index, relevance_score}]}` | unverified | not run |
| llamacpp | `{model, query, documents[], top_n}` | `{results:[{index, relevance_score}]}` | unverified | not run |
| mtplx | `{model, query, documents[], top_n}` | `{results:[{index, relevance_score}]}` | source | not run |
| omlx | `{model, query, documents[], top_n}` | `{results:[{index, relevance_score}]}` | unverified | not run |

"verified" rows are the two ADR-006 marks "Confirmed". "source" means the shape was read from the server's own source code
(MTPLX: `/v1/rerank` in `mtplx/server/openai.py`, youssofal/MTPLX 2.12.2), not yet observed live. The five "unverified" rows are exactly
ADR-006's open gap ("resolved by a live smoke test against each server, not by guessing"). The mapping table is **not frozen yet**
for those six: run the live smoke, paste its output over the "Live result" column, and flip each status to verified.

**Infinity** (`michaelfeil/infinity`) is named in ADR-006 but its endpoint and JSON were never captured ("Gap"); it is deliberately not supported until a shape is confirmed.

MTPLX serves reranking and embeddings from the same daemon as chat (opt-in: `--reranker-model` / `--embedding-model`; an unconfigured endpoint answers 404). Scores for the Qwen3-Reranker family are yes/no probabilities, and a jina-style reranker scores the whole list in one pass, so MTPLX is never split (`too_large` above `maxDocs`, default 256). Optional request fields `instruction` and `return_documents` exist; only `return_documents:false` is sent.

Notes: TEI's field is `texts`, not `documents`. vLLM and llama.cpp serve `/rerank` and `/v1/rerank` (`path` option; default `/v1/rerank`).
Hosted APIs (Cohere, Jina, Voyage) are listwise: a call with more than `maxDocs` documents fails with `too_large` rather than being
split, because scores are only comparable inside one call. TEI, vLLM, llama.cpp and oMLX score pairs, so oversized sets are split and
merged. **Rerank scores are never comparable across rerankers** (ADR-006).

## Configuration

```jsonc
// Hosted
{ "provider": "voyage", "model": "voyage-3", "dimensions": 1024, "secretName": "voyage.key" }
// Self-hosted TEI with an e5 prefix scheme
{ "provider": "tei", "model": "intfloat/multilingual-e5-small", "dimensions": 384, "baseURL": "http://127.0.0.1:8080",
  "queryPrefix": "query: ", "passagePrefix": "passage: ", "revision": "<pinned commit>" }
// Aggregator, identity = pinned upstream
{ "provider": "openrouter", "model": "openai/text-embedding-3-small", "dimensions": 1536, "secretName": "openrouter.key", "pinnedUpstream": "openai" }
// Rerank
{ "provider": "cohere", "model": "rerank-v3.5", "secretName": "cohere.key" }
{ "provider": "vllm", "model": "BAAI/bge-reranker-v2-m3", "baseURL": "http://127.0.0.1:8000", "path": "/rerank" }
```

Validation is strict and aggregated: unknown option keys, credentials or query strings in `baseURL`, a missing `baseURL` /
`secretName` / `pinnedUpstream` where the provider needs one, and bad numbers all fail at construction with a `ConfigError`
listing every issue with its path (`embedding.baseURL: required for provider "tei"`). Defaults: embed timeout 15 s, 3 attempts;
rerank timeout 5 s, 2 attempts (ADR-006). `dimensions` is always required: it is part of the identity and is checked against every response.

## Behaviour that holds for every adapter

- **Retry** only for `rate_limit`, `overloaded`, `network`, `timeout`: equal-jitter exponential backoff. `Retry-After` is honoured up to
  `retry.maxRetryAfterMs`; a longer one is returned to the caller as `rate_limit` with `retryAfterMs` instead of sleeping.
- **Response validation:** count equals inputs, every vector has the configured dimension, every component finite (checked after float32
  conversion, so `1e39` is caught), zero vectors rejected when normalising, index permutation complete. Messages carry counts and indexes, never values.
- **Normalisation:** `normalize` (default true) L2-normalises the returned vectors client-side.
- **Redirects:** never followed. Any 3xx is `bad_response`; the credential is never replayed to another host.
- **Size:** the response body is capped (`maxResponseBytes`, 32 MiB embed / 8 MiB rerank) by content-length and while streaming.
- **Deadline** per attempt covers the body read; a caller abort is `aborted`, never `network`.
- **Redaction:** the resolved secret (plain, URL-encoded, JSON-escaped) and common key shapes are scrubbed from every error message and `toJSON`;
  adapters never keep a raw `cause`.

## Error classes

| `kind` | Meaning | Retried |
| --- | --- | --- |
| `auth` | 401/403, or the secret could not be resolved (no request is sent) | no |
| `rate_limit` | 429; `retryAfterMs` set when the server said so | yes |
| `overloaded` | 5xx / 529 | yes |
| `invalid_request` | bad arguments or a 4xx the server rejected | no |
| `too_large` | input over the token limit, 413, context-length 400, or too many documents for a listwise rerank | no |
| `network` | connection failure | yes |
| `timeout` | per-attempt deadline | yes |
| `aborted` | caller's `AbortSignal` | no |
| `bad_response` | unparseable, wrong shape, wrong dimension, NaN/Inf, redirect, over the size cap | no |

## Identity

`identity()` is deterministic and frozen. `identityHash(identity)` (`adapter-identity:v1:sha256:<hex>`) covers provider, model, revision / pinned upstream,
dimensions, normalisation, `maxInputTokens`, and both prefixes. It deliberately **excludes** `maxBatch`, timeouts, `baseURL` and `secretName`, so two
endpoints serving the same model share an identity. This hash is the adapter's own; it is **not** the engine's `embedding:v1:sha256:` fingerprint id.
`toFingerprint(identity, endpoint?)` produces the subset of core's `EmbeddingFingerprint` an adapter can state.

## Compatibility probe

`probe(adapter)` embeds a fixed synthetic set (two English paraphrases, a German paraphrase, an unrelated sentence, a query) and checks count, dimension,
finiteness, non-degeneracy, normalisation (when claimed) and that related texts are closer than unrelated ones. The result's `{ ok, error? }` is assignable to
core's `ProbeInput.targetProbe`; it also carries the fingerprint, identity hash and the individual checks. It never throws for adapter errors.

## Egress

`egressHosts({ embedding, rerank })` returns `{ host, port, tls, loopback }[]` (IPv6 hosts bracketed). `toEgressConfig()` maps that onto the shape of core's
`EgressConfig` and reports plain-http, non-loopback hosts (core refuses those). The package only *declares* hosts; enforcement stays in `packages/core/src/egress`.

## Tests

- `pnpm --filter @plur1bus/embedding-adapters test`: unit and fixture tests, synthetic fixtures only, no network, no real keys.
- `test:coverage`: line coverage of the package.
- **Live smoke** (`test/live/`): skipped, and reported as skipped, unless `PLUR1BUS_LIVE_EMBED=1` **and** the target's variable is set.
  Keys: `OPENAI_API_KEY`, `GEMINI_API_KEY`, `COHERE_API_KEY`, `JINA_API_KEY`, `VOYAGE_API_KEY`, `OPENROUTER_API_KEY` (+ `PLUR1BUS_LIVE_OPENROUTER_{MODEL,UPSTREAM,DIMS}`).
  Local: `PLUR1BUS_LIVE_{OLLAMA,TEI,VLLM,LLAMACPP,OMLX,MTPLX}_URL` (+ `_MODEL`/`_DIMS` where the server does not report them) and
  `PLUR1BUS_LIVE_{TEI,VLLM,LLAMACPP,OMLX,MTPLX}_RERANK_URL`. Model/dimension defaults are overridable with `PLUR1BUS_LIVE_<P>_MODEL` / `_DIMS`.
  The rerank suite records only the *structure* (key names, JSON types) of each live response and prints the Markdown mapping table at the end.

## Follow-up: wiring into core/engine

Out of scope here. Concrete hook points:

1. **Egress:** merge `toEgressConfig(egressHosts(...)).config` into `egress.allowHosts` / `allowPorts` / `allowLoopback` (`packages/core/src/egress/policy.ts`),
   and send the adapters' `fetch` through the core egress gate (`createGate`/`createEgress`) by passing it as `deps.fetch`. Surface `plaintextNonLoopback` as a config error.
2. **Target fingerprint:** `packages/core/src/embedding-migrate/target.ts` (`targetFromModel`) only builds pinned *local* models today. A remote target would feed
   `toFingerprint(adapter.identity(), baseURL)` through the engine's `embeddingFingerprintFromNormalizedConfig` so the id equals what the engine derives; map
   `adapter-identity` to the engine id there, never compare the two directly. The engine still runs local-transformers embeddings (`engine-config.ts`), so the engine
   must first accept a remote provider block.
3. **Readiness:** pass `probe(adapter)` into `ProbeInput.targetProbe` (`packages/core/src/embedding-migrate/probe.ts`, called from `driver.ts`); its `error` text is credential-free.
4. **Re-embedding:** `ReembedEngine.batchSize` (`port.ts`) should come from `identity().maxBatch`; a driver that embeds itself would call `embed(..., {inputType: "document"})`.
5. **Recall:** query embedding uses `inputType: "query"`; rerank is the recall-path optional step with its 5 s budget and a fallback to unranked order on any `AdapterError`.
6. **Secrets:** back `getSecret` with the host secret store; the config files only ever carry secret *names*.
