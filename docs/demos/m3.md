# M3 demo and acceptance evidence

Use a disposable harness home and the integrated M3 branches. The web UI must connect to the served API and real core/supervisor. Browser layout suites use a typed mock for deterministic UI states; they do not prove real provisioning, storage or authorization.

## Start the served stack

Use Node 24.21.0 and pnpm 10.28.0. On this Mac the Node installation is `/Users/cyberblade/.node24/bin`; use the corresponding installed Node directory on another host. A fresh source-demo home is isolated from the installed harness. `setup` below uses the normal hash-verified runtime installer and may download the pinned runtime/payload; it is not a fixture or an inference acceptance claim.

```sh
export PATH=/Users/cyberblade/.node24/bin:$PATH
export TMPDIR=/private/tmp # macOS: canonical path; on Linux use /tmp
export M3_DEMO_HOME="$(mktemp -d "$TMPDIR/plur1bus-m3-demo.XXXXXX")"
pnpm gen
pnpm build
cargo build -p plur1bus
target/debug/plur1bus --home "$M3_DEMO_HOME" setup --profile host --non-interactive --no-service
target/debug/plur1bus --home "$M3_DEMO_HOME" daemon stop
PLUR1BUS_NODE="$(command -v node)" PLUR1BUS_CORE_JS="$PWD/packages/core/dist/core.js" target/debug/plur1bus --home "$M3_DEMO_HOME" daemon start
node packages/api/dist/api.js --home "$M3_DEMO_HOME" --web-root packages/web/dist
```

The stop/start pair ensures that the disposable supervisor uses the freshly built source Core. At the end, stop that same disposable supervisor; retain its audit/licence evidence only after checking it contains no secrets.

Open the loopback URL printed in the ready record. Keep credentials out of screenshots, terminal history and the demo report. Use the native/VPS account bootstrap from Phase 3, or the desktop installer's existing owner setup for a bundled installation.

## Walkthrough

1. **Wizard:** complete Your account (native/VPS), Name & persona, Main model, Switchboard, Memory, Backups and optional Import. Complete the supported E5-small Memory selection first. For an NC model, demonstrate explicit confirmation and inspect the persisted actor, time, licence, model and exact revision, then demonstrate the actionable refusal when public engine generation validation or the requested migration target is unavailable. Do not present that refusal as successful Gemma/Jina wizard completion: criterion 1 remains partial. Demonstrate the non-interactive E5-small fallback separately.
2. **Two agents:** create two agents; repeat the first submission with its idempotency key and verify there are still exactly two. Pause and archive one. Offer an export before delete and show the explicit refusal while the engine erasure API is absent.
3. **Direct chat:** as a Member, create a chat, stream its answer, fork and archive it. Sign in as another Member and show that the first Member's chat and user-scope memories cannot be retrieved. Create an incognito chat and compare the disposable home's file tree before and after.
4. **Break-glass:** demonstrate a refused transcript request, then an authorized time-boxed request with a reason. Inspect the audit record and affected person's notice. Show that expiry removes access.
5. **Remote and pairing:** local hides the pairing card. Tailnet reports unavailable Tailscale without falling back. Network requires explicit confirmation and TLS; pair a device using the fingerprint-bearing payload, show a wrong pin being rejected, and demonstrate an announced trust rollover. Remote Owner/Admin login requires a second factor.
6. **Accessibility:** switch between light and dark, navigate by keyboard, open and close compact sheets, and inspect pages at 400, 960, 1440 and 2560 CSS px. A 1440-pixel window at 200% browser zoom has an effective 720 CSS-pixel viewport. Confirm reflow without horizontal text scrolling.

## Reproduce the browser checks

```sh
pnpm --filter @plur1bus/web exec playwright install chromium
PLUR1BUS_BIN="$PWD/target/debug/plur1bus" PLUR1BUS_WEB_E2E_REQUIRED=1 PLUR1BUS_WEB_TRANSPORT_REQUIRED=1 pnpm --filter @plur1bus/web test
```

The required mode accepts only Playwright's installed browser revision. Missing Chromium fails instead of skipping or silently selecting system Chrome. `shipped-conformance.test.ts` derives its routes from `PAGES`, checks both themes at all four widths, and emulates 200% browser reflow with a 720 CSS-pixel viewport and scale factor 2. Every shipped page is also checked with enlarged text under CSS zoom. `settings-conformance.test.ts` additionally loads Passkeys/TOTP and Remote/Devices controls, including company-certificate inputs, staged trust and a typed HTTP-fixture pairing offer, in EN/DE across the same widths and zoom cases. Target measurements follow the [WCAG 2.5.5 inline-prose exception](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html); navigation and standalone links remain measured. Existing pattern tests also exercise CSS zoom, keyboard focus traps, sheets and reduced motion. Axe includes WCAG 2.1 AA and colour contrast; `contrast.test.ts` verifies the token pairs numerically.
