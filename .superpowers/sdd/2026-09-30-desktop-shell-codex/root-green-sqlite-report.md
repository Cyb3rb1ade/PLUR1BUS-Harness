# Root SQLite writer test correction

The intermittent `SQLITE_CORRUPT` at `packages/core/test/import/readonly.test.ts:96` exposed an invalid stress-test expectation. The child process inserts rows and runs `wal_checkpoint(TRUNCATE)` while the test calls `openSqliteReadOnly()` with its default busy policy. If four checked copies fail, `packages/core/src/import/readonly.ts` opens the original file with `immutable=1`, and the test immediately queries that changing file. [SQLite's URI documentation](https://www.sqlite.org/uri.html) says `immutable=1` skips locking and change detection and that changes can produce incorrect results or `SQLITE_CORRUPT`. [SQLite's WAL documentation](https://www.sqlite.org/wal.html) describes checkpoints moving WAL pages into the database file; [TRUNCATE mode](https://www.sqlite.org/c3ref/wal_checkpoint_v2.html) also truncates the log. The observed failure is consistent with this path, although the failing run did not record the returned handle mode.

The test now starts the child writer before probing, requests `onBusy: "throw"`, and accepts only `E_SOURCE_BUSY` with reason `source-busy` from the open call. Every successful handle must be a checked private copy whose row count can be queried. After the child exits cleanly, the test requires a successful copy and reads the rows it wrote. It retains the source-directory whitelist and cleans up the child on assertion failure, with a five-second watchdog. Separate tests still exercise the stable-file immutable fallback and the deterministic four-attempt busy fallback. No production code, importer policy, or generated documentation changed.

Validation with Node 24.21.0: focused `readonly.test.ts` passed 10/10 tests, no skips or failures; root `pnpm typecheck` passed. Both commands were bounded (`timeout 30s` and `timeout 120s`). The controller owns the full root test gate.

The production detect policy still opens a genuinely changing source as `immutable=1` after retry exhaustion, as specified in `docs/import.md` §8.2 and `docs/superpowers/specs/2026-09-28-plugin-distribution-and-migration-design.md` §B.5. The SQLite contract means detect can still report wrong data or fail on such a source. Changing that policy requires a separate design decision; this test correction does not claim to remove that risk.
