# Source reading and snapshots

`SourceReader` owns one run's live source read graph. It consumes exactly the six operations from `@plur1bus/remote-fs`; detectors, skill scanning, entity readers, store comparisons and copy preparation use that same port. Native target configuration, target reports, ledgers and target staging remain a separate local authority. Existing CLI report paths continue to name the original source.

`SourceOptions.reader` and `CreateSnapshotOptions.reader` accept `{fs, root, remote?, signal?}`. `root` is the original configured authority. A selected descendant is resolved through that already-confined port before traversal; it never becomes authority for a newly opened connection. SFTP access paths remain slash-based even on a Windows host. The source path mapper independently handles configuration paths written with another platform's syntax.

SQLite and Lance libraries only inspect private local copies. The reader copies through the port, verifies content hashes and directory names, closes native handles, and removes temporary staging on every exit. `fingerprint()` contains only read-set hashes and names. `verify()` rechecks those facts; repeated reads consume the backend's cumulative budget again. Raw source file contents are not retained in the read-set descriptor.

`createSnapshot` dispatches an injected reader to the asynchronous producer. The producer checks source markers before traversal, enforces file, total, count, depth and deadline limits, refuses linked destinations, and writes private directories/files with 0700/0600 protection. A failure removes only the newly owned snapshot directory. The caller owns successful snapshot cleanup when the run finishes or its rollback retention ends. The older WSL tar/helper implementation remains for compatibility; product source services and the packaged host producer inject a read-only port.

Snapshots omit credential files and stores. Supported source configurations retain credential names and declaration forms while dropping values, command arguments, working directories and credential-bearing URLs. MCP slot declarations and manual setup reasons remain available for inert import candidates. Only an explicitly authorized owner secret lease may separately acquire source values; those values never come from the sealed snapshot. Consumers verify the private snapshot anchor and complete file manifest before parsing it.

`discoverReaderSources` probes configured roots, known user-home parents, default source homes and declared profile roots. It does not recursively search unrelated directories. Additional paths must already have passed the host's Owner check. WSL distribution metadata is injected by a trusted local enumeration; stopped distributions are never opened by this helper. Opaque remote WSL images are reported as images and are never mounted or treated as parsed source homes.

Run the importer tests with the workspace test runner. `remote-reader.test.ts` builds the locked native worker and separate in-process SFTP fixture, then exercises both source families through the actual transport. The suite covers SQLite, Lance, skills, entity reads, source immutability, credential sealing, path authority, limits, cancellation and the Windows host wire namespace. `source-entity-port.test.ts` also proves that direct offline importers use the injected port. No installed SSH daemon is required.
