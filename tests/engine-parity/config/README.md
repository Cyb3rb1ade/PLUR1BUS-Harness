`startup.json` is generated by the actual Core startup configuration functions, using synthetic configuration files and SQLite licence receipts. It contains configuration and licence metadata only; it does not run models, produce embeddings, or access model artifacts.

Regenerate with `pnpm --filter @plur1bus/core gen`. The Core parity test recomputes the complete file; Rust runs the same generator with `--check` and evaluates every case through `rpc::config::load`. Both suites also require startup to preserve the input files and directories.

`${HOME}` replaces only paths belonging to the temporary test home, so the same vectors run on Windows and Unix. Explicit path overrides remain inputs. The generator uses Core's read-only config reader, `buildEngineConfig`, persisted licence gate, and the pinned engine's validation-only helper. No expected startup decision is hand-authored.

Rust's documented refusal of WAL-mode licence ledgers remains an additional filesystem policy: opening those through SQLite's read-only mode can create coordination files. Its separate regression test checks refusal without side effects; it is not relabelled as a Core parity result.

Untyped Core configuration/ledger failures are normalized to the existing Harness comparison category `E_CONFIG_INVALID`; typed policy/provider errors retain their actual code and reason. These fixture categories do not add a wire error code.
